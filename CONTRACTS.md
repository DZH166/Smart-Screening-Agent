# Internal implementation contract

Python package `hsd_tool`, Chinese end-user interface, v1.9.0. Local Flask server + browser interface, bundled Windows executable. Default binding is loopback; explicit LAN mode provides browser-owned employee upload, processing and result download on one host. Client originals remain unchanged. Original XLSX and ZIP files are uploaded to this LAN host; authorized safe previews may then be sent to DeepSeek through the host backend. With AI enabled and a usable Key, whole-library candidate retrieval and complete independent local verification run concurrently. Disabled/unconfigured AI retains the complete local path. Original XLSX, ZIP and AI files and local paths are never sent to DeepSeek. The browser never calls the provider directly. No AI production qualification is shipped or activated by this workflow.

Historical v1.8.0 validation: 786 Python tests, four Node checks, production-script syntax and compileall passed; actual Windows portable acceptance covers host admin/DPAPI, independent employee sessions, >2 GiB upload/ZIP64, original-byte/WPS preservation, real 60-row regression and persistent private records after normal shutdown. Production inputs (32) and runtime files (1215) are bound by SHA256. That release went live on port 8818 with the saved Key unchanged, still evaluation-only; no real provider calls or second physical-PC validation were claimed. Exact measurements, failed experiments, browser automation timeout and scope are recorded in `docs/performance-v1.8.0-verification.md`. Current v1.9.0 execution and delivery evidence belongs in `docs/ai-first-v1.9.0-verification.md`; historical measurements do not establish this release's throughput.

## Workbook module (workbook.py)

`inspect_workbook(path: str, work_dir: str, sheet_name: str | None = None) -> dict`

Return `{sheets:[{name,hidden}], sheet_name, rows:[{id, row_number, number, image_path, issue}], reserved_numbers:[str]}`. Row IDs are `r<Excel row>`. Absolute image paths are extracted to work_dir and omitted from public snapshots. Read the first visible sheet by default. Image-bearing rows only; include unreadable image references with issue. Read column A number, B picture for current fixed template; preserve displayed leading zeros. `reserved_numbers` includes existing numbers in column A, including rows without pictures. Ignore huge empty/formatted trailing regions. WPS DISPIMG/cellimages required. Any supported floating drawing must associate an anchor to column B explicitly. Never include hidden sheets by default.

`write_numbered_workbook(source: str, destination: str, sheet_name: str, assignments: dict[int,str]) -> None`

Update only blank column A cells at assigned row numbers. Preserve every other XLSX part and all WPS images/drawings. Refuse replacement of any nonempty source number. Use ZIP/XML surgical updates (ordinary spreadsheet roundtrip destroys WPS-specific image features). Destination must differ from source and must not preexist. No sample workbook changes.

## Matching module (matching.py)

`scan_and_match(source_path: str, rows: list[dict], work_dir: str, progress=None, *, texture_workers:int=2) -> dict`

Input AI folder (recursive) or zip. Must reject traversal/symlinks, check actual disk availability and structural/file-count/decoded-pixel limits; no fixed file-byte, expanded-byte or compression-ratio cap, decode legacy Chinese zip names, preserve originals. Render PDF-compatible AI previews locally (first page; multi-page files must be flagged for review instead of auto acceptance). Source extraction under work_dir only. Return `{files:[{id,name,relative_path,source_path,preview_path,issue}], matches:[{row_id,status,file_id,candidates:[{file_id,score}],reason,evidence}], warnings:[str]}`. `evidence` carries every signal behind the decision: method, colour distance, candidate gap, pixel RMS, changed / major-changed share, worst region, unexplained-content residual, inliers, coverage, MAE and thresholds. These are diagnostic data; the employee screen defaults to the business reason, with detail collapsed. Status is `auto`, `review`, or `unmatched`. IDs are deterministic `f0001` etc. Score is 0..1 similarity, never probability. Fail closed for near duplicates / reused file candidates; do not force a global assignment merely to obtain one-to-one matches. `progress(message: str, current: int, total: int)` is optional. All preview images remain under work_dir. Individual bad AI files are reported without aborting every readable file. Source AI bytes must remain unchanged.

v1.3.0 adds independently checked interpolation-edge pixels, detailed scale/phase measurement, measured repeated-pattern periods and complete candidate-content verification. `matching_verification.py` owns coverage proofs. Do not wrap an artboard as a presumed motif period: a period must be observed and validated across the query, then reproduce the complete candidate. Colour and coherent local differences remain blocking evidence. The historical v1.2.0 regression baseline is 44 local auto / 16 review; the unrelated unpublished 47 / 13 draft is not merged.

`evidence_version:2` retains separate `channels.features` and `channels.texture`, each with score/strong/auto_ok, metrics, failed_checks and alignment. `selected_channel` identifies the actual decision path; AI may not cherry-pick metrics across channels. Alignment describes candidate-to-query geometry, dimensions, measured matrices, query/source/ink coverage and independently checked edges. `competition` binds every evaluated file and score, credible rivals and completion status. A weak shared fragment does not claim ownership from a complete validated match; actual supported competing claims still require review. IDs only identify files; names/order/reference answers never prove identity.

v1.8.0 uses one bounded `_TextureCache` per matching call. Keys bind prepared pixel SHA256, dimensions, transformation/resize parameters and a scratch implementation version. Reusable values include resized arrays, content bounds/histograms and the already-computed coarse result needed by precision verification. Eviction or a cache miss recomputes work; it does not reject an input or impose an upload-size limit. This is not a persistent/cross-task answer cache and does not reuse AI opinions. Source hashes and all later original/export integrity checks remain mandatory. Never substitute filename, path, length or mtime for content identity.

Pixel arithmetic retains the same float32 subtraction, absolute error and normalization while avoiding redundant RGB conversions/intermediate frames. Phase selection computes only its actual RMS criterion; full metrics are still evaluated for selected verification. A later expensive percentile may be skipped only when unchanged preceding limits have already rejected the candidate. Colour, coherent local differences, full content/ink coverage, competition and automatic-acceptance thresholds remain authoritative. Optional texture workers are limited to 1 or 2, preserve candidate order and never render PyMuPDF or mutate geometry RNG/ownership from concurrent threads; no running job changes OpenCV's process-wide thread setting. Default/selected performance policy and actual equivalence results belong in the versioned performance report.

## Whole-library retrieval and local verification (v1.9.0)

`prepare_matching(source_path, rows, work_dir, progress=None) -> PreparedMatching` safely extracts, renders and decodes once without comparing pairs. Its task-local rows are deep-copied; appearances are read-only and bind decoded pixels to actual encoded-image bytes. `file_bindings` includes every prepared query/preview plus source AI SHA256. `match_prepared(prepared, progress=None, *, proposals=None, texture_workers=2, verify_sources=True)` checks all bound files before and after matching. The immediate legacy `scan_and_match` wrapper skips only this additional delayed-source pass, retaining render-time protections. Objects are private to one task, never public JSON or shared across employee jobs.

When `AiSettings.runtime()` privately declares `matching_workflow:'ai_first'`, enabled AI with a usable Key chooses the new path automatically. This is not an employee-supplied switch or a qualification override. Preparation first creates the shared immutable inputs. The AI coordinator starts one local CPU child future while retrieving candidates; production local verification receives the complete prepared library and **no model proposals**. The model neither narrows that comparison nor supplies positive local matching evidence. Both results join under the original job identity, operation token and revision; only the independently computed local result controls row status, ownership and numbering.

`ai_first.py` uses protocol `hsd-ai-first-retrieval-1`. Each request includes all eligible readable single-artboard candidates; only query groups may be split. It keeps full overviews and ordered exhaustive wide-strip panels, randomizes anonymous query/candidate IDs and independently shuffles both lists. Filenames, row numbers, original documents, paths, local verdicts and reference maps are absent from prompt text. Image text is untrusted data. Duplicate complete candidate previews, corrupt/unreadable previews and multiple artboards cannot be resolved by asking the model to choose. Oversized full libraries fail explicitly rather than silently omitting rivals; local verification continues where valid.

The strict wire response is `{matches:[{query_id,candidate_id:null|string,verdict:'same'|'uncertain',reason}]}` with every query present exactly once and no unknown IDs. Missing/duplicate identities, malformed or contradictory structure fail. Returned collisions are preserved; there is no forced one-to-one allocation or elimination. Retrieval's `same` is always a suggestion, never qualification or acceptance. Source/preview hashes, actual implementation and current-run identity are rechecked; paid stale/failed replies remain recorded but cannot change the current plan. Local CPU failure or any source/image change blocks publication/export even if the provider returned `same`.

The parent remains busy through the join. Its CPU child does not replace the parent's token, revision or AI queue identity. Resource queue counting includes a queued/running CPU child. During overlap `progress.phase:'parallel_verification'` has zero total and displays AI-group and local-image counts separately; no summed percentage is meaningful. When only one stage remains, `ai_retrieval` or `local_verification` reports that stage's actual counts. Every exit path drains accepted child work before completing the parent future; normal close waits for accepted futures/operations before shutting down executors. After both paths finish, the coordinator rechecks original workbook/snapshot/archive and all prepared source/image bindings, then commits one final effective plan. AI errors preserve their usage and valid local results, never invent successful matching.

```text
job.matching_mode = 'ai_first' | 'local'
job.ai_retrieval = {status,message,usage?,proposed?,error_code?}
row.ai_retrieval = {candidate_id:null|string,verdict:'same'|'uncertain',reason,
                    outcome:'suggestion'|'error'|'skipped',reason_code?,model?}
progress.phase = 'parallel_verification' | 'ai_retrieval' | 'local_verification'
```

The employee UI calls retrieval a suggestion requiring confirmation on unresolved rows. A local `auto` row may say local verification passed; model `same` alone never changes that state. A retrieval suggestion differing from the currently selected/local candidate stays visible. Short reasons are shown once, longer explanations expand separately from old `row.ai_review`; no pair-check booleans or qualification are invented from retrieval. Accepted batches go straight to the existing summary; automatic items have no mandatory viewing step.

`queue_seconds` accumulates waits in separate resource queues; parallel waits can overlap, so it is not the elapsed union of all waiting. Do not sum it or overlapping phase times into batch wall time.

The original optional `/ai-review` route remains available after readiness for eligible remaining questions, under its existing pair protocol and independent business-qualification gates. Initialize its independent summary so server-computed `can_retry` remains visible. `job.ai_retrieval.usage` and `job.ai_review.usage` are distinct; each actual attempt reaches the cumulative ledger exactly once. Unknown usage stays unknown and USD remains an estimate. Existing multi-Key retry budgets, global 429 cooldown and absence of a monetary cap remain unchanged.

Full retrieval plans, anonymous input/implementation bindings, every attempted/uncalled group, failure, collision and sanitized response are checkpointed under private `task_records/<job>/ai_first_runs/`; they also remain in private export evidence. They are not browser download members or qualification artifacts. No request bodies/images/credentials are retained in public debug or Git/releases. Current business qualification binds eleven modules, including `ai_first`; no existing ten-module qualification silently survives. Real API regression and synthetic controls do not constitute new independent business accuracy or qualification; the reserved 10.12 batch is not used. Current evidence and limitations: [v1.9.0 verification](docs/ai-first-v1.9.0-verification.md).

## Service + UI API (owned by root)

Flask defaults to loopback. Explicit `--lan <private-IPv4>/<prefix> --lan-input-root <dir> --lan-output-root <dir> [--port <port>]` binds only the specified RFC1918 interface and admits only the supplied CIDR. The legacy input root must exist; the legacy output root is created if needed and must be outside it. These roots constrain host-only path compatibility requests; employee uploads use managed directories under `data_dir` instead. LAN paths reject escapes through symlinks/junctions and UNC/network-share paths. The service is not public internet hosting or remote desktop access.

Remote clients first use `POST /api/lan/login {code}` with a matching Origin. The per-start random code is persisted only in the local data directory's `instance.json` as `lan_access_code`; it must not appear in logs, Git, releases or remote snapshots. Host-only config may display it for the operator. Sessions expire after 8 hours without sliding renewal. Login attempts are limited per client address; excess attempts return 429. `POST /api/lan/logout {}` ends the remote session and requires the usual CSRF header. Local-host pages can enter directly.

Each LAN browser session receives a random `employee_id` stored in the signed session cookie. Every job-scoped route checks `_owner_id` against that session, including reads, images, resolve, undo, AI retry, export, download and host output-opening. A mismatched owner receives 404, even from the host browser. Login creates a new identity; there are no employee accounts, cross-browser recovery or reassignment APIs. All users share backend capacity and the host's AI settings, not a current batch. Different tabs in the same browser session share ownership and use revision checks to avoid stale changes.

`--data-dir` isolates employee uploads/tasks/results. `--settings-dir <existing-host-data-dir>` supplies the shared DPAPI-encrypted Key, AI settings, usage ledger and qualification registry without copying credentials; the same Windows user must run it. Remote clients never configure or obtain the Key, and their cumulative-usage endpoint is forbidden. Per-batch usage remains in their own summaries. Tasks remain process-local; logout/relogin, cookie removal or switching browsers loses the old task access identity, and process shutdown loses tasks. Do not advertise persistent employee task recovery.

Browser gets X-HSD-Token from `window.HSD_TOKEN` populated in index.html template placeholder `__HSD_TOKEN__` using a JSON literal. All POST requests, including multipart upload, use this header except access-code login. Remote session authentication and request token/origin validation both apply. Standard failures are `{error: Chinese string}`, HTTP 400/401/403/404/409/413/429 etc. JSON is not cached. Never return keys, raw provider request bodies or private process settings. LAN public job snapshots redact managed host paths.

- `GET /api/config` -> `{prefix:'HSD', digits:4, last_start:1, last_workbook:'', last_source:'', last_output:'', version:'1.9.0'}`. LAN mode adds `{access:{lan:true,remote:bool,upload:true,upload_limits:{workbook_bytes:null,source_bytes:null,total_bytes:null}}, active_job_id:str|null}`; only host-side `access` also contains `code`. Historical paths are blank. `active_job_id` and last start number refer only to the current browser owner's newest job, never another employee.
- `POST /api/pick` `{kind:'workbook'|'zip'|'folder'|'output'}` -> `{path: str}` (native host dialog; forbidden for remote clients)
- `POST /api/jobs` `{workbook_path,source_path,output_root,start_number:int}` -> `{id}`; local path workflow unchanged. In LAN mode, host-only compatibility API validates legacy roots and assigns the browser owner; remote requests are forbidden. The LAN UI on both host and remote uses upload instead.
- `POST /api/jobs/upload` -> `{id}`; LAN only, `multipart/form-data`, exactly one `workbook` XLSX file, one `source` ZIP file and one `start_number` string (1–9999), no other fields. Applies session, Origin and X-HSD-Token checks. All three public byte limits are null (no application byte cap). The multipart request explicitly overrides Flask's default 64 KiB JSON-body cap; JSON endpoints retain it. Non-file form memory and part-count controls remain. Writes streams to `data_dir/uploads/<random-batch>/workbook.xlsx` and `source.zip`; filenames are display-only. Validates true XLSX/ZIP content, traversal, links, encryption, repeated names, entry counts, 1–500 AI files and actual disk availability; no fixed per-AI/expanded-byte or compression-ratio limit; failed uncommitted uploads are removed. Output is confined to `data_dir/employee_outputs/<random-batch>/`.
- `GET /api/jobs/<id>` -> full owned job as below, poll 1s while queued/importing/matching/ai_review/exporting. CPU work (1 worker), AI batch coordination (2), global AI cases (2) and export (1) have separate resource pools. Queued snapshots add `queue_stage:'cpu'|'ai'|'export'`; `queue_position` describes that resource queue. AI-disabled/no-network batches do not wait behind AI requests. Multiple employees upload independently without sharing task state. Long work stays off the request/UI thread. Editing/exporting is unavailable for that busy job; shutdown and settings writes also reject active per-task planning operations. Shutdown drains accepted work and rejects new mutations.
- `POST /api/jobs/<id>/resolve` `{row_id, file_id: str|null, revert?: bool, expected_revision?:int}`; null means skip, `revert: true` restores the matcher's own verdict for that row, otherwise confirm mapping; returns job. Refuse duplicate file ownership.
- `POST /api/jobs/<id>/undo` `{expected_revision?:int}` -> job with `last_undone_row_id`; restore the last employee change, recompute numbering, increment revision. `can_undo` indicates availability.
- `POST /api/jobs/<id>/export` `{expected_revision?: int}` -> `{id}`; background export. UI sends the revision of the reviewed summary. A mismatch rejects stale confirmation; reload the job and show the new summary. No need to view every auto result before export.
- `GET /api/jobs/<id>/image/row/<row_id>` and `/image/file/<file_id>` -> preview image; `?size=thumb` requests a proportional thumbnail. Stable job-specific URLs and ETag; LAN uses private no-cache/must-revalidate so every reuse checks the session and owner, while non-LAN keeps private immutable caching. Never append random timestamps.
- `GET /api/jobs/<id>/download` -> ZIP attachment `HSD编号结果.zip`, LAN owned upload jobs only, after `status:'done'` and `download_ready:true`. Exports only service-authorized rows after summary confirmation; contains only the explicit final plan's numbered AI copies and exactly one numbered workbook, under one result folder. CSV/JSON, previews, diagnostics and request records remain host-private and are never ZIP members. Atomically packages verified output members and validates the stored archive SHA256 before serving. Invalid, altered, incomplete or another owner's downloads fail; never supplies arbitrary filesystem paths.
- `POST /api/jobs/<id>/open-output` `{}` -> `{ok:true}` (only completed job output; forbidden for remote clients).
- `POST /api/shutdown` `{}` -> `{ok:true}`; exits the local process when no task is busy; forbidden for remote clients. Closing the browser alone is not shutdown.

In LAN mode `resolve`, `undo` and `export` require `expected_revision` for both host and remote pages. A stale revision returns 409; the UI refreshes that owner's job rather than silently overwriting another tab's change. Only final server states make rows exportable; neither upload nor download bypasses summary confirmation, ownership, numbering conflicts or source-change checks. Managed upload/output/download files remain host-side copies; browser attachment download saves the result to the employee's computer without changing their originals.

Job schema:

```text
{id, status:'queued'|'importing'|'matching'|'ai_review'|'ready'|'exporting'|'done'|'error',
 progress:{message,current,total,phase?,step_label?}, error:null|string, revision:int, can_undo:bool,
 sheet_name, workbook_name, source_name, start_number, prefix:'HSD',
 stats:{total,auto,ai_auto,confirmed,review,unmatched,skipped,exportable,
        pending,needs_attention,new_numbers},
 rows:[{id,row_number,number,planned_number,
        status:'auto'|'confirmed'|'review'|'unmatched'|'skipped',
        file_id:null|string,candidates:[{file_id,score}],reason,reason_code?,
        evidence?,diagnostics?,ai_review?,ai_retrieval?}],
 files:[{id,name,relative_path,issue}], warnings:[],
 output_root, output_target, output_dir:null|string, report:null|dict,
 queue_position:int, download_ready:bool, download_name:null|string,
 matching_mode?:'ai_first'|'local', ai_review?, ai_retrieval?, timings?}
```

`auto` includes both local and qualified AI acceptance; `ai_auto` is a subset of `auto`. Local auto count is `auto - ai_auto`. `confirmed` means employee confirmation only. `pending = review + unmatched + skipped`, while `needs_attention = review + unmatched`. `new_numbers` counts accepted blank-number rows; `exportable = auto + confirmed`. The UI's `awaiting` count and default “需要处理” filter include `review + unmatched`; skipped rows remain separate. Automatic entry to the summary depends on `review === 0`, so a batch with only unmatched/skipped items remaining does not require opening those rows. The summary states all unresolved counts. “Continue” and “All results” still provide optional access to unmatched rows and correction.

All unresolved rows retain their source numbers in output. Only matched rows with blank source numbers get planned new numbers. In non-LAN mode `output_target` is the destination folder; LAN public snapshots describe downloading to the employee computer instead of exposing host paths. Existing numbers remain exact, including non-HSD prefixes. Duplicate or unsafe output numbers block affected rows; no overwrites. Source changes invalidate affected decisions/export. An export error may return the task to `ready` with `error` populated so the UI can explain and retry. Inputs are typed/picked local paths in non-LAN mode and managed browser uploads in employee LAN mode. Session storage may remember the current owned job ID/selected row/filter for page refresh; no tasks survive process shutdown. Uploads and employee output copies are separate from disposable job caches and require host-side lifecycle management; do not claim shutdown deletes every uploaded original.

## Resource scheduling and private records (v1.8.0)

This section retains the v1.8.0 resource/record foundation. v1.9.0 additionally joins concurrent whole-library retrieval and a complete local CPU child as specified above; enabling AI no longer waits for local review eligibility before the retrieval stage.

`JobManager` has CPU 1, AI batch coordinators 2, shared AI case workers 2 and export 1. `pool` remains the CPU executor compatibility alias. Queue order/position is per resource, not an invented whole-batch percentage. Disabled AI, absent usable credentials or a batch without review rows follows the lightweight local completion path instead of waiting for an occupied AI coordinator. Key count never scales concurrency.

`job_operation(id, internal=False)` is a per-job reentrant operation guard. Look up/count operations under the short global map lock, release it before acquiring the task lock, and never acquire a task lock while holding the global lock. APIs check revision/status and apply one consistent plan under the task operation. AI computes snapshot eligibility, images, hashes, gate evaluation and planning outside task/global locks, then briefly checks the current run token, status, expected revision and original row binding before committing. Its own stable-order commits advance the expected revision; unrelated/user changes do not. A stale response is retained as invalidated evidence with its actual usage and cannot overwrite the current selection. Shutdown rejects new external mutations and drains accepted CPU handoffs, AI coordinators/cases and exports before cache cleanup; accepted internal work uses `internal=True`.

Each AI batch has at most two in-flight cases using the shared two-worker executor. Only disjoint candidate sets overlap; shared candidates serialize. Apply results in original case order/ID regardless of completion order. Before and after the request, preserve full-case/implementation/source checks, including non-exported competitors. Stop submitting after a terminal provider/pool error, drain all started calls, and mark every uncalled case. `run_finished` is emitted only after started work converges; success, failure and interruption retain an ending trace. Retry budget stays at two actual attempts per case.

Each completed attempt records only `{attempt,key_id?,code,elapsed_ms,usage,not_called?}`. Codes and usage are sanitized, with no credential, preview, request body, local path or original exception. Success returns and `ReviewError` carry `attempt_history`; the case observation retains all attempts, the planned case ID, actual response/usage and invalidation/failure state. An interrupted coordinator keeps the original error/history and marks interruption rather than replacing it with a successful-looking partial result. A definite pre-HTTP factory/credential failure is `not_called` with zero requests; an unexpected failure after entering the client review preserves unknown usage. Batch/lifetime accounting merges each case once, pool counters account per actual attempt, and removal of an in-flight key cannot erase process-wide usage.

`record_directory(id, 'ai_runs'|'export_records')` validates the private root, task ID, section, parent containment and absence of links/reparse points. Persistent host records are:

```text
data_dir/task_records/<job_id>/
  ai_runs/ai_observations_<run_id>.json
  export_records/<export_id>/处理记录.json
  export_records/<export_id>/对应关系.csv
  export_records/<export_id>/待处理清单.csv
```

All planned AI cases are checkpointed before requests. Completed attempts checkpoint immediately; case completion/interruption preserves every result and failure. Artifact mutation/publication uses separate short artifact/write locks outside task/global locks, exclusive temporary files, fsync and atomic replace. Export records retain matching evidence, complete AI run/attempt history, pending/skipped rows and provenance. `jobs/` is disposable scratch; `task_records/` survives normal close/cache cleanup, including non-exported failed AI runs. These paths are internal, never downloadable through a new route, Git content or release assets. Persistent records do not provide persistent browser/task recovery.

The final server plan explicitly allows `已编号AI/<effective-number>.ai` and one `<source-stem>_已编号.xlsx` under the result folder; managed upload's workbook stem is `workbook`. Both the output folder and employee ZIP exclude CSV/JSON, previews, diagnostics and request records. Do not recursively package everything or filter only a few extensions. Completed-export reuse binds revision, plan, exact member allowlist, original/source hashes, verified output hashes and private-record manifests. Retry/repeated download retain these checks. ZIP64, streamed member writes, temporary cleanup, atomic publication and full archive SHA256 verification remain; compression is a build policy, not a new employee setting.

Timings separate batch wall time and resource queues from accumulated AI case queue/prepare/request/verify work; parallel work sums can exceed wall time. Use [the v1.8.0 performance report](docs/performance-v1.8.0-verification.md) for actual repeated measurements and unchanged/untested boundaries. `tools/benchmark_ai_cases.py` checks package isolation and preserves complete synthetic artifacts/debug with `source:'synthetic_mock'`, `synthetic_transport:true`, `real_api_calls:0`; its fixture-only serialization also tags workflow-created files. Mock waiting is not real provider latency, independent business validation or production qualification.

## Employee presentation and interaction (v1.5.0)

This release changes the static interface and interaction work only. Existing business routes, job schemas, matching/numbering decisions, DeepSeek request and qualification gates, ownership checks, upload limits and export validation remain authoritative and unchanged. No new endpoint or front-end-only acceptance state is introduced.

Import shows the applicable local path controls or employee XLSX/ZIP upload controls plus the batch start number and primary submit action. The fixed prefix appears as an example, not another editable field. Template, file requirements and original-preservation information are available under `import-help`. Local mode keeps folder/source and output selection; employee mode never exposes host path configuration. Upload and background progress identify the current stage; unknown totals remain indeterminate, and queue position is shown separately.

The default review list contains `review + unmatched`, with skipped rows outside that queue. A compact status line highlights work remaining. Automatic results never require viewing. The comparison retains a stable image area, wide-strip stacking, enlargement, selected-candidate identity and a visible action footer. Alternative candidates, complete paths, similarity metrics and diagnostics are optional expansions. AI-specific differences, file issues, contradictory responses and an AI review concerning another selected candidate remain visible. A suggestion without effective automatic acceptance says it requires employee confirmation, while actual employee-confirmed/skipped states remain correctly identified.

Summary primary counts are exportable, new numbers and pending; the original row treatment is stated whenever pending is nonzero. Local auto, AI conditional auto and employee-confirmed counts are under `summary-processing-details`, using `local = auto - ai_auto` so the subset is never counted twice. Per-batch AI usage and estimated USD cost, including unknown usage, stay under batch details. One explicit summary action sends the current revision to the existing export route, without a second duplicate confirmation or an all-images prerequisite. Completion emphasizes result download/open and the next batch; records remain optional.

Host sharing information, AI configuration, cumulative cost and shutdown are grouped under `host-management`. Remote pages keep that entry hidden, but hiding controls grants no permissions: existing server-side host/owner/session/CSRF checks still enforce every request. Saved keys are never rendered into any page or state. Employee details cannot obtain host cumulative usage.

Indexing and keyed list-node reuse reduce redundant lookup and whole-list replacement; candidate changes update candidate-specific content while preserving the query image and relevant view state. Search is debounced, previews use job-specific URLs and existing owned thumbnail endpoints, and neighbour preloads are deduplicated per task. A task change clears transient preview/view caches. No new cross-session image cache is added. Busy controls prevent duplicate submits, success follows a valid server response, and failures retain recoverable state. Revision 409 refreshes current server state visibly; it never silently converts a failed save into success. Polling is limited to active background states, backs off for retryable failures and stops for terminal/authentication/task-loss responses.

`tools/ui_fixture_server.py` serves explicit synthetic UI scenarios for private local acceptance only; it does not load production jobs, settings, credentials or provider calls. `tests/test_ui_interactions.js` checks semantic and DOM invariants, not real browser timings or AI business accuracy. Before/after screenshots and raw local measurements stay under ignored `tmp/`; only sanitized verification conclusions belong in documentation.

## DeepSeek settings, usage and workflow

- `GET /api/ai/settings` -> host sanitized `{enabled,configured,model:'deepseek-flash',mode:'evaluation'|'validated',key_source:'saved'|'environment'|'none',key_persistence,price_date,prices,price_basis,storage_warning,validation:{qualified,mode,model,categories,counts,message}}`. Remote responses are limited to `{enabled,configured,model,mode}`.
- `POST /api/ai/settings` `{enabled?:bool,api_key?:string,clear_key?:bool}` -> sanitized settings; host only, forbidden for remote clients. Blank/omitted key preserves the saved value. A new key and `clear_key:true` together are invalid. Windows persists the key with DPAPI CurrentUser; no plaintext fallback. Environment variable `DEEPSEEK_API_KEY` is used only when no saved key exists. Clearing a saved key does not clear that variable. No browser-readable existing key, mode toggle or validation override.
- `GET /api/ai/usage` -> cumulative usage below; host only in LAN mode, remote requests return403. Each employee's own batch usage remains in its job summary.
- `POST /api/jobs/<id>/ai-review` `{}` -> `{id}`, background `ai_review` (first `queued` for LAN jobs). UI shows this only when `job.ai_review.can_retry` is true. Server checks owner, ready/configured/enabled, batch limits and actual case eligibility. It never overrides employee decisions.

job.ai_review = {mode,eligible,reviewed,suggested_same,auto_passed,
                 unresolved,skipped,usage,message,can_retry}
row.ai_review = {verdict?,candidate_id?,reason,checks?,differences?,protocol_diagnostics?,gate_failures?,
                 outcome,reason_code,gate_reason?,model?,request_id?,category?}

         cache_hit_tokens,cache_miss_tokens,unknown_usage_requests,

         cost_is_upper_bound,cost_incomplete,currency:'USD',price_date}

Default mode is evaluation with no production qualification. Suggestions remain `review`; no model text or self-reported confidence can change status. Show the candidate the suggestion concerns, especially if the employee is viewing a different candidate. Errors/skips must not be labelled as model or employee acceptance. Only an actually accepted auto row can be labelled AI conditionally accepted. A request failure is contained to AI review and leaves local results/manual work available.

`estimated_usd` estimates known usage using recorded peak prices. `estimated_usd_upper_bound` is null if any usage is unknown; the UI must state the unknown request count and incomplete cost statistics, never present unknown charges as zero. These USD figures are estimates, not a provider invoice. There is no monetary fee ceiling. Do not confuse finite request/retry limits with a cost cap.

The following payload/eligibility paragraphs describe the optional pair-review path; whole-library retrieval uses its separate protocol above. Preview-only pair-review payloads contain complete overviews and, for wide images, ordered exhaustive panels, task-local candidate IDs and neutral comparison instructions. Measured valid geometry may add an aligned pair and mapped/unmapped coverage diagram, while retaining all originals. No arbitrary crops/tiles or old local verdict are used to bias the model. Only actual plausible rivals are supplied; complete local competition evidence must account for all files, and more than five credible rivals stays manual. No original AI/XLSX/ZIP, filenames or local paths are included as prompt text. Visible text inside design images remains image content. Treat it as untrusted data, not instructions. Keys are sent only in backend authentication to the configured official provider; never in snapshots, logs, reports or front-end storage.

Eligibility is restricted to untouched `review` rows with readable single-page previews and verified source metadata. Duplicate previews anywhere in the batch, duplicate query images, actual competing ownership, number conflicts, unreadable images/multiple artboards and absent credible candidates are excluded before the request. Recheck image/source fingerprints before applying a response and before export. Hard conflicts cannot be overridden by the model.

## Independent validation and conditional automatic acceptance

Policy and prompt versions are `hsd-ai-review-2`. Wire response is exactly `{candidate_reviews:[{candidate_id,verdict,reason,checks,differences}]}`, one entry per locally supplied ID. Pair checks are content_same/colors_same/complete_coverage/extra_content_absent. Each entry describes only its own candidate. Missing/duplicate/unknown IDs or invalid schemas fail. Contradictory verdict/checks/differences are preserved in bounded `protocol_diagnostics.raw_decision`, flagged inconsistent and downgraded to uncertain. Provider bodies, prompts and credentials are never retained there.

The client normalizes the pair response to the existing decision fields. `unique_candidate` is locally derived only from one strict positive and every other supplied candidate explicitly different; identity still requires direct positive evidence. Categories remain geometry_review/texture_review. All five normalized checks must be true, verdict same, differences empty, and chosen candidate the local first. Independent signed qualification, native detail, complete local alignment/coverage, colour/content consistency and complete competition are separate gates. All failures are recorded together as `failed_checks`/`row.ai_review.gate_failures`, so missing qualification cannot conceal other contradictions. A model switching candidates, affirming unreadable detail or contradicting local evidence remains manual.

Case fingerprints bind selected-channel evidence, alignment, all competition scores, every compared preview/source digest (`comparison_inputs`), and the supplied images. Any competitor changing invalidates the earlier proof, even if not exported. Original comparison sources are verified before/after requests and before/after export. Every pair-review run checkpoints all planned cases and the eleven-module `implementation_sha256` before I/O and after each attempt; retries retain earlier failures. Changes during a request preserve the actual reply and charges but invalidate the case for qualification. Export records contain both the latest `ai_observations` and all `ai_observation_runs`; whole-library retrieval records remain separately typed and cannot substitute for these qualification observations.

`tools/run_ai_evaluation.py --synthetic --out <empty-dir> --settings-dir <data-dir> [--prepare-only]` prepares generated labelled cases; without `--prepare-only` it makes real billable calls using the existing settings. Output preserves all planned cases, including failures, plus frozen labels, fingerprints, responses and usage. It never activates business acceptance. Repository-local outputs must stay under ignored `tmp/`.

`tools/validate_ai_review.py --labels <labels.json> --observations <observations.json> --output <report.json>` makes no network calls and reads no key. It requires schema version 1, real `deepseek_live` records of the current protocol, exactly matching unique planned/case/request IDs, a single actual model, image/candidate/source fingerprints, and complete responses. Labels declare `case_id`, `case_fingerprint`, `batch_id`, `category`, `split:'calibration'|'holdout'`, `origin:'independent_manual'|'synthetic_known_truth'|'reference_map'`, `label:'same'|'different'|'uncertain'`, `candidate_ids`, `expected_candidate_id` and `controls`. The response's `case` binds `category`, `candidate_ids` and `image_digests`. Do not reuse query images across independent batches or mix calibration and holdout within a batch.

For each approved category, at least two independent holdout batches must each include a positive, a negative/uncertain case and a useful correctly accepted positive. At least one batch must include independently manually verified real business positives and negatives. Overall, at least two accepted positives and five negatives must cover `color_change`, `local_replacement`, `extra_content`, `shared_subset`, `near_duplicate`, with zero false accepts across all recorded cases. Synthetic data alone or an existing reference map cannot qualify production. Labels are independent and frozen before observing model output; do not relabel origins or omit failed cases to pass.

After reviewing a qualifying report, adding `--activate --data-dir <tool-data-dir>` explicitly signs/stores the qualification locally. The registry checks integrity, binds the actual model, categories, policy/prompt versions and eleven implementation modules (ai_policy, ai_client, ai_images, matching, matching_verification, archive_io, ai_workflow, ai_dispatch, ai_key_pool, ai_admin, ai_first), and expires after 7 days. Observation artifacts must have recorded all eleven implementation signatures at call time, matching the current implementation; activation cannot re-sign old results as newly verified code. Missing/mismatching signatures remain usable only for regression analysis, never qualification. Changed implementations/protocols invalidate the record; an unqualified model/category cannot pass the per-row gate. No production qualification is shipped or newly activated in v1.9.0; implementation changes invalidate older qualification while preserving saved encrypted keys and settings. These are minimum activation prerequisites for the measured scope, not a general accuracy guarantee. The user has reserved 10.12 for later and chosen employee verification of a new business batch.

## Large-file IO (v1.6.0)

Authenticated multipart file parts stream directly to randomized, owner-private staging files under the upload batch, with write-time SHA256 and available-disk checks by 64 MiB windows. Successful parts are renamed on the same filesystem to fixed managed names; failures/interrupted parsing close all streams and clean uncommitted directories. Existing authentication, Origin, CSRF, owner and revision rules remain mandatory. `null` byte caps never coerce to zero or fall back to old defaults; the upload XHR has no fixed elapsed timeout. Empty files, wrong formats, invalid archives, links, traversal, encryption and excess file counts remain errors. A finite decoded image pixel limit is distinct from file bytes.

`JobManager.create(..., input_digests=...)` is an internal receiver-only keyword, not a JSON/form field. The receiver supplies workbook/source SHA256 computed from successfully written bytes. The worker copies the workbook then independently hashes its snapshot, and rehashes the source archive after scanning. Local-path imports still take their original before/after hashes. Export source checks, independent AI copy verification, owner checks and verified download hashing remain. AI copy digests already independently verified are reused in the output manifest; packaging hashes each member against that original digest, including retry/tampering paths.

`archive_io.member_blocks` uses bounded reads and verifies actual decompressed content, declared length, compression EOF and CRC, retaining ZIP header/overlap checks. AI rendering opens file paths rather than a full bytes object; on Windows a read-only sharing lease denies concurrent writers/replacement, with file identity checks. Other platforms rehash after rendering. Workbook non-target parts and images stream through bounded buffers/temporary files; worksheet XML patching retains its original in-memory design, so large XML still depends on actual RAM. No arbitrary byte threshold is substituted.

The new archive IO dependency is included in AI qualification implementation fingerprints and isolated matching-validation signatures. Prior implementation qualification does not silently carry forward. This release changes IO, not matching evidence/thresholds, numbering, AI request scope, prompts, qualification activation or export eligibility.
