# 通用精修原文执行契约

状态：通用实现已保存在独立分支 `codex/ribbon-background-refine`，按用户加速要求仅做必要检查，更广的矩阵留到合并前；未合并、未部署网站。它覆盖丝带的布局参数、独立图案、底纹、分区底纹、边饰和既有可编辑整幅版本，不针对某种装饰写特例。

## 原要求怎样进入执行

1. 保存完整原文与UTF-8 SHA256。服务端按完整标点子句编号，保留所有空白、标点、中文、emoji和引号内文字；不让模型重新书写原文。
2. 规划必须逐条声明目标、修改方式及操作引用。每条修改只执行一次，每个操作必须有原文依据；保留要求不能授权修改。缺一条、目标冲突、超出能力或只执行部分时，图片调用前澄清，不保存或扣成功精修次数。
3. 图片模型实际使用相关原句和保留约束，不使用规划器自由改写的提示词。因此它不能自行把“铺满”改成“少量”，也不能加上用户未要求的柔和、低对比、改字或换色。固定提示只约束编辑范围和未要求内容，不抵消明确的加字等要求。
4. 参数区分设为、增量、百分比、倍数和模糊方向。程序以当前有效值核对计算，不接受引用同一个数字就随意旋转、放大或位移。新版布局还检查实际图案大小、间距、方向与位移，防止数值变化被适配和限幅吞掉。
5. 保存和恢复前重放合同：实际参数、允许派生的图层、未编辑引用、原文绑定、执行记录和下载检查保持一致。恢复不重调模型，任何一项失败保留旧版。

每次仍是一次文字规划，以及每个确实需要修改的图片目标一次生成；相同目标的多条图片要求合并。不新增自动二次精修，不重发未知结果。只应用员工已选素材/排版仍完全在本地执行，零模型调用，不伪造自然语言覆盖记录。

## 页面怎样表达结果

结果保留默认折叠的“查看本次要求”，历史版本对应自己的原文。源哈希、Unicode范围或记录无效时，只显示原文，不显示核对结论。

- 新版程序参数实际核对通过：显示“参数调整已核对”。
- 图片或混合修改：显示“已生成，效果请对照要求”。
- 保留项只显示“约束已传递”，不把它当作模型已保持每处细节的证明。
- 旧引擎仅参数值检查时，明确为“参数已应用，效果需核对”。

不增加逐图确认或下载步骤，不把任务成功、原文覆盖和像素变化称为所有视觉要求已满足。

## 明确的能力与限制

目前参数只支持现有六项及原有限制。未支持的厘米/毫米/英寸、偏移百分比换算先澄清，不把1厘米当1像素。分区排法的整幅横移会串动底纹归属，本轮拒绝这种请求，提示选择单图案调整。先生成底纹、后用纯色完全盖住它的计划会在图片调用前拒绝。

图片编辑保持现有原生尺寸/比例和透明状态策略，不假装已经增加抠图或透明状态转换。能确定与固定请求参数冲突的透明转换在预检拒绝。保留员工已有柔和/原色选择，模型图仍可能因柔和显示而变淡。

原文编号和受控运算能证明没有丢文本、没有无来源操作，并核验支持的程序参数；它们不能证明自然语言的每种表达都被理解正确。复杂同句多目标、矛盾要求、未知参数表达可能需要澄清。生成文字、人物细节、颜色和审美效果仍可能偏差；技术检查、模型自报和有限样图都不是通用语义合格证明。

旧快照、回退及下载不重算；两次成功精修、失败不扣、50小时保留、员工隔离和源文件保护保持。业务图、模型输出、调用记录和截图仅留私有忽略目录，不提交Git或Release。
