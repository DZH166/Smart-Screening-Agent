# v1.17.0 素材流程、批量确认与页面验证

验证日期：2026-10-23。本记录区分真实模型结果、合成页面检查和发布检查。源码提交前的检查记录如下；不可据此认定取得独立业务质量资格，实际云端切换和发布包检查以本版 Release 的发布回执为准。

## 本版变化

- 素材处理改为整图清理一次，再由 DeepSeek 给出完整设计的矩形范围，服务器从清理后的原始像素中裁剪。Seedream 不再逐个生成独立图层。
- 页面持续显示实际处理阶段、已完成原图数量和已生成结果。上游图片请求仍为同步调用；没有把等待时间伪装成模型内部生成百分比。
- 图号助手和素材提取均支持员工选择待确认项后批量确认、撤销最近一次批量确认。批量确认属于员工决定，不计为算法自动通过。
- 管理员“功能区”打开实际工具；提供商配置和员工访问码设置入口归入 Key 账本，并标明对应功能。

## 真实验证范围与调用记录

调用前冻结了两张现有真实素材局部、一张自制双设计图和一张原始复杂拼图的定性期望。期望关注完整设计、文字和内部底板保留、外加干扰清理及可检查的裁剪边界，没有把旧清单数量当作真实答案。未使用留待后续的10.12批次。

真实验证合计 **4次 Seedream 清理、8次 DeepSeek 定位**：首轮4组完整流程，随后两轮各针对缓存清理图进行2次定位对照。后两轮没有重新调用 Seedream。所有请求均收到完整返回并记录实际用量，没有自动付费重试或未知结算状态；这只说明本次接口收敛情况，不证明图片质量。

使用已配置的 `doubao-seedream-5-0-flash-260915` 和 `deepseek-flash`。验证使用隔离的单进程、逐例执行，不修改生产凭据、开关或运行服务。原图、清理图、错误裁剪、请求回执、截图和完整检查记录只保留在私有验收存储，不提交 Git 或发布附件。所有不良结果均保留，没有用后续较好结果替换原始证据。

### 两轮定位对照

仅复用已保存的清理图，每轮每例一次定位，没有重新清理。下表仅记录定位阶段耗时。

| 定位方案 | 复杂拼图返回框数 / 耗时 | 自制双设计返回框数 / 耗时 | 视觉检查 |
| --- | --- | --- | --- |
| 原比例清理图＋坐标网格参考图 | 43 / 17.289秒 | 2 / 5.218秒 | 复杂拼图下方范围偏移、内容缺失和相邻碎片仍明显；双设计范围合理 |
| 等比例方形清理图＋方形网格参考图 | 43 / 16.496秒 | 2 / 4.569秒 | 部分整体纵向偏移减小，但仍有切边及混入邻图；双设计范围合理 |

最终采用 `hsd-material-locate-3-square`。清理图按比例放入1000×1000参考画布，提供已知内容范围及附带坐标线的第二张参考图。服务器只去除自己添加的留白，并将坐标映射回无标记的清理原图裁剪。网格和参考图缩放不会写进裁剪结果。结构、范围、重复或包含关系及资源大小在映射后再次检查。

这一选择使坐标约定和映射可验证，**不代表定位质量已达标**。返回43或45个框都不是准确率、完整率或独立设计数量的答案，也不能将两个合成设计的成功扩大为复杂业务图片验证通过。

## 效果问题与验收边界

- 人物局部整体保留，但面部、头发和裙装存在重绘。
- 花卉标语的主要文字保留，但字形、配色和花卉细节改变。
- 自制双设计的文字与底板保留，但清理阶段引入了渐变或纹理。
- 复杂拼图的外加尺寸说明与可见水印有所减少，但定位仍会切掉人物边缘、鞋子或文字，带入上下相邻图案；最终方案中仍见头像左侧被截、LOVE设计不完整，以及底部多个条纹设计被合成一个大框。
- 实测首轮矩形结果均为不透明背景。矩形裁剪没有完成透明抠图，不能继续承诺每张都是透明素材。
- 复杂拼图首轮裁剪的原生长边仅115—229像素；输出长边4096只是按比例放大，不表示恢复可印刷细节。

**复杂拼图的完整性质量验收尚未通过。** 当前生成结果继续待人工确认，不授予自动质量放行资格。每项保留“估计范围可能切到设计或带入邻图”的提示，并提供重新框选入口；清理可能改变文字、颜色和细节的提示也保留。批量确认不得掩盖已发现的问题，员工仍须依据可见结果决定哪些可用。尚缺新的、独立确认的业务批次，不能报告通用准确率。

## 流式进度与失败处理

应用通过 SSE 推送排队、准备、清理、定位、裁剪、保存和完成等真实阶段。进度数量统计本批已完成原图，不表示 Seedream 内部生成进度。当前已核对的上游图片协议不提供本流程可用的逐像素生成流。

正常连接轮换发送 `renew` 并重新核对权限；这不是任务失败。断线可回到状态查询，终止、换任务、隐藏页面或退出后关闭不再需要的连接。任务归属、会话、预览和下载租约保持独立。

清理和定位分别记录尝试及用量。仅明确拒绝且可安全重试的调用允许该阶段重试一次；定位失败不会重跑已经付费的清理。超时、不完整响应或结果不明时不盲目重发。停止会阻止未发送任务，并等待已发送请求返回或超时、保存结算记录后才显示终止完成。

已使用明确标注的合成接口数据在1366×768和1920×1080窗口检查：素材进度、结果卡片、批量确认及撤销、图号批量操作、管理员功能区入口与配置入口分区。页面验证不额外调用真实模型，也不是 AI 效果或自动通过资格证明。代表性页面截图仅存本机。

最终 Windows 全量回归为 **1938 passed、56 skipped，318.45秒**。8个前端 Node 测试文件全部通过，其中素材交互36项通过。较早的1934项记录只是中间检查，未代替最终代码验证。定位供应商、素材服务、映射后重复/包含检查、未知提交、批量确认原子性、源文件变化、编号冲突、跨员工访问、CSRF和版本冲突均有回归覆盖。

浏览器实际操作通过：素材选择多项并确认、整组撤销、ZIP下载到本机、处理下一批、处理中停止并等待收敛；图号批量确认进入摘要且可整组撤销。1366×768检查主要操作可见，1920×1080核对素材卡片与管理员功能区。测试数据和模拟接口均明确标注，不把页面操作结果当作真实模型质量证明。

用户在发布前追加外背景透明要求，已加入实际 Seedream 清理提示词，并增加真实 Alpha 保留/不透明提示回归。以上4次清理实验发生在该提示词追加前，不代表新增要求已通过真实效果验证。追加后 Ark、定位管线、素材服务与 API 针对性检查169项通过；最终发布包与线上合成验收以 Release 回执记录。
