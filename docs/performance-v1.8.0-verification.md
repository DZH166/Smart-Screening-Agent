# v1.8.0 速度与下载验收

开发基线为 `main@ff31e65fadcee9d48ba1b21af322853576c2f93c`（v1.7.0），没有合并 `deepseek-pro`。本次保留多 Key 管理、DPAPI、实时调试、员工隔离与既有匹配、编号、AI 资格、导出校验规则；没有恢复固定上传字节上限。

交付前已同步远端 `main@5fc0dde`；该提交仅修改 README 标题为“HSD 图号助手”，生产代码与上述基线相同，因此原基线测量仍有效，无需因标题重测。本次保留远端标题和提交历史。

## 实现与边界

- 匹配调用内部复用像素摘要、尺寸、实现版本和处理参数绑定的尺度图、内容边界、直方图及原始粗搜结果。数组缓存预算 64 MiB、最多 512 项；元数据、OpenCV 临时数组和整个进程内存另计。失败不缓存，图片准备结果只读，修改真实像素必须重新准备及计算摘要。不跨员工或批次持久复用匹配意见，原稿变化检查仍执行。
- 减少 float32 临时数组，复用粗搜，已确定不满足原条件时跳过无意义的百分位计算。保留通用浮点、广播、空数组及布局回退，颜色、局部差异、完整覆盖、竞争候选及原阈值不变。几何、RANSAC、PyMuPDF 保持串行；纹样线程按原候选顺序汇总，统一处理归属。
- CPU 队列 1、AI 批次协调 2、全局 AI 案例 2、导出 1。独立案例才并发，结果按稳定 ID 写回；同任务使用独立锁，长计算、网络及文件读写离开全局锁。退出先等已接收操作完成提交，再依次收敛工作池。
- 复用原 ManagedReviewClient/ApiKeyPool，单案例最多两次实际请求；认证/余额异常暂停 Key，网络/5xx 同 Key 重试，429 使原池冷却 60 秒。Key 数量不扩大并发或供应商额度。资格仍绑定十个模块；实现变化使旧资格失效，保留原 Key，无新业务放行资格。
- 每次计划、回包、失败、重试及已付费但失效的结果保留在主机私有 `task_records/<任务ID>/ai_runs` 和 `export_records`。正常退出清理临时缓存后记录仍保留。实时有界事件与持久案例记录含义不同，不对员工开放其他任务记录。
- 服务端最终计划生成显式输出清单，结果目录和员工 ZIP 只含 `已编号AI/<编号>.ai` 及唯一编号 Excel。额外文件不能被递归发现后混入包。保留部分导出、摘要确认、原行不变、重试和重复下载检查。
- 每成员最多采样 192 KiB（大文件头/中/尾各 64 KiB）；大文件三段各自用 level 1 节省至少 10% 才压缩，否则 STORE，避免头尾文本掩盖中部已压缩内容。小文件检查完整样本。采样只选择压缩方法，不能证明文件身份。实际成员仍逐字节 SHA 对照原 manifest，保留 ZIP64、流式写、fsync、暂存清理、原子发布及下载前完整 ZIP SHA。

## 测量方法

Windows、10 核 16 线程、约 32 GiB 内存，同一 Python 环境、同一输入，顺序运行测量，测量期间不运行其他重负载测试。正式匹配前后均用 `tools/performance_benchmark.py`，没有 cProfile。基线、中间稿及最终默认配置各用三个独立进程，每个进程处理两次；同版串行受控配置另用三个独立进程各处理一次。首次指新应用进程及空任务 scratch，磁盘 OS 缓存未清空，而且输入摘要校验会预读文件；不能称 OS 冷盘测试。重复处理仍重新读取、解包、渲染及建任务缓存，不能当持久缓存命中。

真实回归输入仅 10.10 的 60 张和现有编号表；10.12 未使用。`tools/compare_matching_runs.py` 对候选顺序、归属、状态、原因、完整证据以及文件绑定做递归比较（浮点绝对/相对容差各 1e-7），同时验证实际输入 SHA 与完整轮次。现有映射仅为回归参考，不是独立人工业务留出集，不据此宣称通用准确率。

阶段计时包含关系必须区分：特征、纹样、精细验证是比对的子阶段；phase/period 也是纹样子阶段。并行累计工作秒可能超过墙钟，均不能相加成整批时间。读取计时已含在总墙钟内；图像解码等未单独包装部分不伪装成某一个热点。下列测量分别覆盖不同阶段，不能将各表中位数相加为员工整批耗时。
