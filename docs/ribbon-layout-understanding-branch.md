## 案例怎样补充

本轮重新取得并目视查看了公司图库中的 297 张不同预览，并挑选、放大复核 21 张高清案例；连同原有 13 张，形成 34 张教学案例。每种排法提供 2–3 个公司案例，说明应该看哪里、需要哪些素材，以及与程序实际排法的差别。这是抽样研究，没有遍历整个图库，也没有训练或微调模型。

案例按当前排法分别标记：

- `direct`：可以直接参考其排列关系，仍不是原图、色彩和设计内容的一键复刻。
- `partial`：只借鉴其中一部分，例如主辅层级、边饰或分区。页面明确显示不同之处，不把这种案例描述为等效的生成效果。

同一案例用于不同排法时，可以有不同的说明和匹配类别。只有当前排法下的 `direct` 案例才有资格被员工明确选作 AI 首稿参考；仅浏览案例不调用模型，也不改变作品。服务端同时校验排法、资格、私有白名单和完整文件摘要，不能依靠隐藏按钮限制发送。

另增加 42 个程序生成的演示案例，每种排法 3 个；14 张入口缩略图与它们一起组成 56 张公开 WebP。演示使用代码绘制的兔子、花、文字牌和装饰等原创图形，通过真实 v3 排版引擎生成。案例编号 `1/3/6` 是固定变体编号，不统一表示输入图案数量：整幅定位仍是一张完整设计，分区、场景和边饰各自使用适当的素材组合。

公司图仍只放实例私有案例目录，不进入 Git、公开静态目录或 Release。公开演示图在前端源目录和运行静态目录分别保存；发布工具为全部 112 个路径绑定固定 hash，旧 v2 图和 hash 保持不变。

## 六种复杂排法的实际变化

新作品绑定 `seamless-unit-v3`。此次改动集中在以下六种排法，其余八种保留 v2 的几何行为。

| 排法 | 本分支实现 |
| --- | --- |
| 随机散点 `scatter` | 在二维区域内安排完整图案，逐个旋转、检查碰撞和循环接头；固定种子可复现。可明确指定小装饰，间距变化只扩展横向分布，不重新打乱图案。 |
| 组合场景 `scene` | 区分主图、配角与小装饰；主图与配角保持共同基线和大小层级，小装饰放在实际可用空间。间距与装饰排放解耦，避免间距调大后反而更挤。 |
| 上下边饰 `bordered` | 未明确指定的图案都保留为主体；只有显式边饰图案才进入上下窄带，另可选独立完整边条。调整间距保持完整重复组数量稳定。 |
| 左右分区 `split` | 默认等分，前后两组分别排入左右区域；各区使用相同行数和高度预算，可分别选择底纹。 |
| 分区拼接 `panels` | 三个等宽区域分别安排完整图案组与独立底纹；以完整组重复，剩余空间转为间隔，不裁掉图案补齐。 |
| 上下分区 `stacked` | 上下两区分别安排前后两组，使用相同高度预算和行数，保留完整素材及独立底纹来源。 |

三档密度仍控制实际大小、间隔及排法允许的行数。过窄图案无法保留至少一个像素、超出资源范围或局部调整会碰撞时明确拒绝，不缩坏、遗漏素材或伪装成功。示例展示和几何检查不等于印刷质量验收。

## 图案用途与历史版本

生成或选择配置时，可传入 `selection.pattern_roles`，键为当前所选素材 ID，值由排法限制：

| 排法 | 可选用途 | 省略时默认 |
| --- | --- | --- |
| `scene` | `main`、`support`、`accent` | 第一张主图，其余配角 |
| `scatter` | `main`、`accent` | 全部主图 |
| `bordered` | `main`、`border` | 全部主图 |

这三种排法必须至少有一个主图。其他排法不接受非空用途配置。服务端校验所选素材、归属、用途枚举和排法；保存时将素材 ID 映射为稳定 `pattern_slots` 的用途记录。编辑图案内容只替换该槽位的素材引用，不丢失用途或修改其他图案。用途改变参与有效变化判定与版本签名；同模式省略配置保留原用途，显式空配置重置为默认，换排法且未填写用途时按新排法默认处理。

新作品使用 v3，已有 v1/v2 作品继续使用其父版本引擎。旧模板记录、缩略图、素材、版本和下载不重算、不覆盖。两次成功精修、失败不扣、回退不返还、50 小时保留、员工隔离和模型请求规则保持。无效或越界的几何修改在图片编辑前拦截，不新建版本、不扣成功次数。
