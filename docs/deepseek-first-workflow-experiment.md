# DeepSeek 全候选检索实验（2026-10-19）

结论：让模型直接寻找对应关系有速度潜力，但本轮结果不支持把整套生产流程交给模型直接放行。三轮真实 60 图检索中，有一轮偏离既有核验映射并产生原稿归属冲突；合成控制也出现不应明确选定唯一原稿的 `same` 建议。保持线上 v1.8.0 的本地可靠匹配、合规模型复核、疑难项人工确认及最终导出校验。

这是隔离研究，未修改线上页面、匹配门槛、编号、AI 资格、上传规则或导出规则，未激活资格，也未将实验结果写回员工任务。生产基线 `main@f5d262f`，开始时远端 main 相同；没有合并另一个安装包/网关分支。10.12 未使用。

## 测试内容与公平边界

1. 当前正式 AI 阶段：将已冻结的 53 自动 / 7 人工本地结果交给原 `ai_workflow.review_job`；7 项均符合现有发送条件。原完整预览、长条分段、对齐证据、源文件复验、Key 池及最多两次尝试都保留。该计时排除先前 CPU 匹配，不能称整批时间。
2. AI 优先检索：60 个查询、全部 60 个原稿候选，匿名 ID、查询和候选顺序预先洗牌；不发送文件名、行号、编号、路径、本地排名或旧答案，不利用现有匹配缩小候选库。模型只给对应关系建议，没有可靠自动通过资格。
3. 固定合成控制：7 个独立种子查询、8 个候选，包括缩放和留白正例、颜色变化、局部替换、额外内容、仅共享局部及低清无法区分两原稿的歧义。标签在调用前冻结、调用后评分，不据结果调整输入或提示词。

模型实际响应名称均为 `deepseek-flash`。真实请求通过现有 `ManagedReviewClient`、`ApiKeyPool`，保持每组最多两次尝试、认证/余额暂停、同 Key 网络重试及 429 冷却。原 DPAPI 设置只读复用，已知用量通过原跨进程锁账本计入累计费用。未发送 XLSX、ZIP、AI 原件；只发送预览和完整分段。

全量检索使用明确独立的 `experimental_ai_first_v1` 协议，不是原生产逐候选核验协议。生产仍为 32MiB/40 预览的复核请求；实验按官方当前 48MiB 请求体及 600 图上限预检，员工上传设置不变。官方仍会按像素数量缩放图片，完整输入不能证明模型检查了全部细节。[图像接口说明](https://api-docs.deepseek.com/zh-cn/guides/vision/)

## 真实测量

同一台 10 核 16 线程主机，无 cProfile。正式 AI 计时期间停止其他编码、测试及重负载。供应商网络和提示缓存仍会变化；后两轮不能当作首次未缓存耗时。

| 项目 | 实测三轮（秒） | 中位数（秒） | 范围 |
| --- | --- | ---: | --- |
| v1.8.0 原本地 60 图处理 | 157.853 / 156.918 / 155.250 | 156.918 | 复用已绑定同版实现和相同输入的正式测量，含读取/解包/预览/匹配，不含 AI、人工及导出 |
| 本轮只读取/解包/渲染 60 图 | 13.603 / 12.805 / 13.081 | 13.081 | 新建目录，不执行本地候选精细比较，不调用模型 |
| 当前正式 7 项 AI 阶段 | 27.104 / 27.601 / 26.742 | 27.104 | 冻结本地结果之后，原资格、准备、请求和复验完整执行 |
| 全候选模型检索阶段 | 45.038 / 39.058 / 41.462 | 41.462 | 每轮 4 个顺序请求，全 60 查询完成，预览及传输编码已准备；不含导出和可靠放行验证 |
| 7 查询合成模型检索 | 2.870 / 2.344 / 2.245 | 2.344 | 全 8 候选；只作合成风险探针 |

全量检索还实测一次 **41.352 秒**前置准备：读取/摘要 0.602 秒，无损 WebP 编码及逐张解码像素一致性校验 38.794 秒，分组序列化/验证 1.955 秒。三轮 API 使用同一份已编码内容，不把后两轮当成新批次免编码。该准备只有一次完整有效观测，不虚称三轮中位数。合成控制准备另为 0.987 秒。

因此，本轮证明了候选检索阶段的速度潜力，**没有测得“安全完成整批”的可直接比较提速百分比**。各阶段范围不同，不能把中位数相加、扣除不利开销或拿第一次模型回答与完整本地安全处理相比。原本地测量完整口径见 [v1.8.0 性能记录](performance-v1.8.0-verification.md)。解压、编号、源文件和归属保护、WPS 定点写回、复制与导出仍须本机程序执行；Tool Calls 的实际函数也由调用方执行。[工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/)

## 编码与分组的实际成本

完整 60 查询和 60 候选共生成 322 张全幅/分段输入，没有小拼图或静默删图。PNG 请求 92,795,116 字节；无损 WebP 请求仍为 70,565,722 字节，无法单次内联发送。WebP 编码前后尺寸与 RGB 像素逐字节相同。JPEG95 4:4:4 的 47,373,830 字节仅做过预检，有损方案废弃，未调用接口或纳入速度结果。

以 20 查询分组时，最后一组超过上限；请求前按固定顺序二分该组。最终每轮为：

| 查询数 | 每组候选数 | 图像数 | 请求字节数 |
| ---: | ---: | ---: | ---: |
| 20 | 60 | 194 | 45,411,686 |
| 20 | 60 | 187 | 44,192,896 |
| 10 | 60 | 154 | 41,838,128 |
| 10 | 60 | 156 | 44,932,436 |

每轮总计发送 176,375,146 字节，因为完整候选库在四组重复。全部组及三轮在任何请求前冻结，没有找到某个相似对象就提前结束，也没有按剩余文件强制分配。重叠候选的组顺序执行，没有靠额外并发抢跑。

## 结果与风险

### 现有 60 图仅作回归

| 轮次 | 符合既有映射的建议 | 偏离映射 | 归属冲突组 | 模型 `same` |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 60 | 0 | 0 | 60 |
| 2 | 60 | 0 | 0 | 60 |
| 3 | 59 | 1 | 1 | 60 |

第三轮偏离发生在原本需要人工处理的一项，模型把它指向另一张本地可靠项已占用的原稿。原服务端归属校验必须保留，不能让模型解除。全部原始建议、异常和冲突仍保存在主机，实验实际自动通过为 0。

同一批 60 张重复三次不是 180 个独立业务样本。旧核验映射也不是新的独立人工留出集；不能据此给出整体准确率或自动放行资格。前两轮全命中不能抵消第三轮问题。

### 合成控制

两个正例三轮均正确选择；四个明确差异负例三轮均 `uncertain`。部分 `uncertain` 附带候选 ID，不能把它计为错误放行。低清歧义例在第 2、3 轮均明确选定一个候选并标 `same`，是两次违反已冻结真值的明确建议。

该歧义具有可检查的构造依据：两个原稿像素不同，但 BOX 缩小至 512×128 后与查询逐像素相同，区别信息已丢失。不能仅凭查询唯一确认原文件。如果直接把模型 `same` 当成通过，这两次就会错误解除歧义。当前实验和线上均未如此处理，实际生产错误自动通过没有新增。

这是 7 个程序生成的查询重复三次，不是独立业务验收，不能计算通用业务错误率。工具的通用评分含“非空候选偏离预期”字段；报告另按 `verdict` 区分候选建议与明确 `same`，避免把不确定建议夸大为误放行。

## 当前 AI 阶段还能优化哪里

正式三轮 7 项复核的累计工作时间中位数：准备 17.132 秒、实际请求 12.892 秒、返回后的复验 15.544 秒。它们在两个 worker 间重叠，不能相加成 27.104 秒墙钟，也不能直接换算为墙钟占比。准备与复验包括源文件摘要、完整候选绑定及图像处理，不全是网络等待。

优先方向是：在可信的任务快照/文件保护范围内减少重复编码和重复校验；减少相同预览重复传输；再用独立业务批次验证“模型候选检索＋本机完整核验”的通道。保留全部竞争候选检查，不能只验证模型指定的文件或降低门槛。以上方向尚未实现，不宣称已有收益。

## 费用、失败记录和验证边界

本轮实际 43 次请求均获得符合传输/结构要求的响应，无接口失败或重试，未知用量为 0。语义上的偏离和错误 `same` 已单独保留，不因 HTTP 成功而算业务正确。用量：844,555 输入 token、12,861 输出 token，按项目配置峰值单价估算合计 **US$0.102579156**，不是供应商账单。

全 60 检索各轮估算 US$0.075648072 / 0.004536600 / 0.004547400；缓存命中差异很大，不能推定每个新批次都是后两轮费用。原 7 项复核四轮总计 US$0.012786960，合成三轮 US$0.005060124。实际所有尝试已写入共享累计账本，未改 Key 设置。

保留的实验问题：

- PNG、WebP 单请求超限及原 20 查询分组超限都是调用前失败，0 次 API；所有预检结果和废弃 JPEG 大小测量保留，没有静默换成缺图结果。
- 最初当前 AI 的第三轮（27.074 秒）末 8 秒与初版 PNG 编码重叠。完整保留该轮，但正式对照取前两轮加编码停止后的补测 26.742 秒，按明确的干扰原因排除，而非挑选更快结果。四轮共 28 次真实请求都计入费用与历史。
- 初版私有 AI 测量脚本在三轮响应与结果已完整保存后，用超范围 `limit=2000` 请求调试快照，最终退出 1；接口实际允许分页 1–200。该诊断导出失败记录保留，修正分页后的补测正常退出 0。没有为修日志重复调用那 21 次接口；逐案例及每次尝试记录均完整保存。

原始输入、逐项对应、图片、模型结果、用量明细、失败日志仅保存在忽略目录 `tmp/deepseek_workflow_compare_01/`。Git 仅保存通用实验工具、合成控制生成器、单元测试及本汇总。64 项相关 Python 检查通过；本轮没有修改 Windows 程序或重新发布便携版本，线上仍为已验证的 v1.8.0。未使用其他独立业务批次、未测实体第二台电脑、员工人工时间或长期限流/供应商负载。

## 复现入口

```powershell
.venv\Scripts\python.exe tools\prepare_ai_first_controls.py --out tmp\ai-first-controls-new
.venv\Scripts\python.exe tools\benchmark_deepseek_first.py --manifest tmp\ai-first-controls-new\input-manifest.json --labels tmp\ai-first-controls-new\labels.json --out tmp\ai-first-controls-prepare --prepare-only
```

真实调用使用另一个空 `--out` 目录，去掉 `--prepare-only` 并添加 `--settings-dir` 指向原 DPAPI 设置目录；不通过命令行传 Key。会发送预览并产生费用。默认完整三轮，所有尝试和失败均保留，不取得自动通过资格。

真实输入 manifest 为 `queries: [{id,image_path}]`、`candidates: [{id,image_path,source_path,source_sha256,page_count:1,issue:null}]`；ID 必须匿名且顺序独立打乱。标签文件为 `origin` 和 `expected: {query_id:candidate_id或null}`，只在请求后评分。大批次可用 `--query-batch-size 20`，每个组仍包含完整候选库，超字节限制会在调用前二分查询组；一个查询加完整候选库仍过大时明确失败，不丢候选。原件和本机路径不进入请求。
