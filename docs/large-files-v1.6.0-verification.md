# v1.6.0 大文件处理验收（2026-10-16）

本版以 `main` 的 `10c7ec55aa03d2ffd22a57a18eb0fa88f64eedd8` 为基线，先保存完整生产代码，再修改上传、归档、预览与导出 I/O。匹配判定通道、阈值、编号与 DeepSeek 请求协议不变。业务样本、截图、原始测量、日志、密钥及结果仅保存在本机，不随 Git 或发布包交付。

## 已实施

- 表格、ZIP、整次 HTTP 上传、单个 AI、展开 AI 总量、工作簿内部部件与编码图片不再有固定字节上限；正常文件不因高压缩比被拒绝。`/api/config` 三项 `upload_limits` 返回 `null`，前端不回退旧值或将 `null` 当零。
- 通过认证后，multipart 文件流直接落本批隔离目录，同步计算成功写入字节的 SHA256，再同卷改名。省去 Werkzeug 临时文件到管理目录的一次整份复制。按 64 MiB 写入窗口检查实际磁盘，短写、磁盘满、请求中断或解析失败明确失败并清理未提交临时文件。
- worker 复用内部可信上传哈希，省去表格和源 ZIP 各一次导入前读取；仍独立哈希表格快照、重新检查扫描后的源 ZIP，导出前后继续核对原件。JSON/form 不能提供或覆盖这些可信哈希。
- AI 预览改为路径读取与固定块哈希；Windows 读取租约拒绝原稿被同时写入或替换。预览参数不变，非 Windows 保留渲染后整份复核。
- 工作簿图片使用可寻址暂存流，非目标内部部件流式写出；目标工作表保持原定点修改方式。AI 副本独立回读校验后，复用其哈希生成清单，下载打包仍对每个成员重新计算哈希，避免被修改的内容成为新基线。
- ZIP 流检查实际长度、CRC、完整压缩流、路径和重叠；包含 BZIP2/LZMA 的解压循环也限制单次输出缓冲。新增小模块纳入 AI 资格和独立验证的实现签名，不沿用旧实现资格。
- 上传 XHR 不再有固定 30 分钟超时；同值进度事件不重复更新 DOM。网络中断、取消、服务端错误及重复提交保护仍在。

仍保留每批 1–500 个 AI、归档最多 10000 项、工作簿最多 20000 个部件和表格图片 4000 万像素等数量/解码检查；这些不是文件字节上限。有限磁盘、RAM、网络、原稿复杂度和排队仍有实际边界，不能承诺任意大文件都能完成。特别是目标工作表 XML 仍需在内存中定点修改。

现有 60 张 10.10 回归：升级前后均 **53 自动 / 7 人工 / 0 无法处理**，所有行候选顺序、分数、源文件 SHA、状态和原因码逐项一致。两次总耗时 284.659/325.165 秒，均有不同并行测试负载，**不可据此比较速度**。该批只验证判定未变，不代表独立业务准确率；10.12 批次未使用。

实际 Windows v1.6.0 便携程序：

## 本次上线

新入口为 **http://192.168.0.160:8816/**，v1.6.0 独立数据目录与进程，不覆盖 8815/8807/8805 的任务。专用 Windows 防火墙仅允许本版 exe、本机 192.168.0.160/32、TCP 8816 和来源 192.168.0.0/24，未开放公网。

实际运行的 exe、构建清单及三份静态资源哈希与验收包一致。沿用原 Windows 用户实际保存的设置目录，已启用/已配置/来源 saved，员工继续共用 Key，不复制或回显密钥。两个线上独立会话完成合成上传、自动匹配、摘要导出、下载和 10 次隔离检查，10.891 秒，累计 API 用量无新增。它不是 DeepSeek 接口的新业务验证。

实际浏览器在 8816 页面选择上述 101 MiB 表格和超过 2 GiB 的 ZIP，均无大小错误；点击上传后直接进入摘要（可导出 1、新增编号 1、未处理 0），无需逐图检查。前后页面与合成摘要截图仅存本机。浏览器自动化桥接本身多次等待超时，不将这些时间归为应用卡顿，也不据此报告网页上传速度。

未由第二台实体电脑验证带宽和连通；浏览器登录最长 8 小时、无跨浏览器/重启任务恢复规则保持。原始文件仅传局域网主机，DeepSeek 外发范围继续仅限原授权预览。
