# 丝带助手：功能与架构（开发前必读）

更新：2026-10-29。依据来源：`hsd_tool/ribbon_gateway.py`、`hsd_tool/ribbon_settings.py`、`ribbon_backend/*`、
`ribbon_frontend/src/*`、`docs/ribbon-integration.md`、`docs/ribbon-providers.md` 与线上 v1.20.0（`ff02d98`）。
标「未验收」的条目是文档与代码明确留下的边界，不要当成已完成能力对外承诺。

## 1. 它是什么

第三个员工工具，做**丝带/装饰条设计**：员工选图案、排版和底图，生成首稿；再用一句话提修改要求（精修），
最多两次成功精修；可以回退到父版本、按版本下载 PNG。入口在同页左侧「丝带设计」（`#ribbon`），
沿用原站员工登录与管理员权限，不另开账号、不新增公网端口。

与另两个工具的关系：**代码独立**（`ribbon_backend/` + `ribbon_frontend/`），只在三处复用宿主：
登录身份、Provider 密钥池与用量账本、50 小时保留常量（`hsd_tool/retention_window.py`）。

## 2. 员工流程与规则

1. 新建作品 → 选 1～12 个图案（透明 PNG）、1 种排版、1 张底图 → 生成首稿。
2. 首稿是**确定性排版合成**，不重画整幅图，**不占精修额度**；底图可以由 AI 生成（单独任务，也不占额度）。
3. 精修：一句话要求（1～2000 字）→ 语言模型出受控计划 → 执行参数调整或图片编辑 → 合成新版本。
   每作品最多 **2 次成功精修**；失败/需要补充说明不扣次数；回退**不返还**已用次数。
4. 回退：只能退到**当前版本的父版本**，按 `expected_version_id` 校验，版本记录全保留（有分支）。
5. 下载：始终绑定**选中版本**的不可变文件（`master.png`），校验 sha256；下载不改当前版本。
6. 保留期：个人作品、历史版本、个人上传素材 **50 小时**；成功生成/精修/回退重新计时；
   共享素材库、模板、输出配置不随个人作品清理。

## 3. 进程与请求链路

```
浏览器 #ribbon
  └─ /static/ribbon-loader.js  ← 按需 import /static/ribbon/ribbon.js（ShadowDOM 挂载）
     └─ 同源请求 /api/ribbon/*（写操作带 X-HSD-Token）
        └─ Flask 宿主：会话/来源/CSRF 守卫 → ribbon_api（server.py）
           └─ RibbonGateway：注入身份 wsgi_environ['hsd.ribbon_user']
              └─ a2wsgi ASGIMiddleware → FastAPI（独立事件循环线程 hsd-ribbon-api）
                 └─ Service（SQLite WAL）＋ 单后台 worker 线程（持久队列）
```

要点：

- 身份只来自宿主注入的 `wsgi_environ`，**不读浏览器 header/cookie/JSON 里的 owner 或 role**；
  本地模式用 `session['ribbon_local_owner']` 随机值隔离浏览器。
- 下载、预览、上传都以**资源租约**（`LeaseRegistry` + `resource_lease`）保护到响应关闭，
  清理器看到持有租约的 owner 会整批跳过。
- 仍是**单 Gunicorn worker**；ribbon 的 FastAPI 与后台 worker 都在这个进程里，不额外起进程/端口。

## 4. 数据与目录

| 位置 | 内容 |
| --- | --- |
| `storage/data/ribbon/ribbon.sqlite3` | 全部业务数据（WAL） |
| `storage/data/ribbon/assets/` | 上传/派生素材 |
| `storage/data/ribbon/jobs/<job>/<attempt>/` | 每次尝试的中间图、`artifact.json`（不可变） |
| `storage/data/ribbon/templates/`、`jobs/*/master.png` | 模板缩略图、版本母版与预览 |
| `settings/ribbon_model_settings.json` | 丝带模型设置（Key 加密，独立加密域） |

## 5. 数据模型（SQLite）

| 表 | 作用 |
| --- | --- |
| `users` / `sessions` | 仅在 `demo`/`local` 模式使用；线上 `hsd` 模式用宿主身份，`ensure_external_user` 按 owner 建行 |
| `assets` | 素材：`kind`(pattern/background)、`sha256`、`source`(provider)、`is_demo`、`shared`、`derived_from`、`retained_at` |
| `templates` | 排版模板，`(id, version)` 主键，`mode` + `rules_json` + 缩略图哈希；改版新增版本不覆盖 |
| `output_profiles` | 输出规格（宽高/DPI/PNG），`active` 单选，历史作品保存自己的配置快照 |
| `designs` | 作品：`current_version_id`、`successful_refinement_count`（CHECK 0..2）、`active_job_id`、`revision` |
| `versions` | 不可变版本：`parent_version_id`、`sequence`（0=首稿）、`snapshot_json`、`master_path`/`preview_path` + 双哈希、`render_kind`、`provider` |
| `jobs` | 任务：`kind`(generate/refine/background)、`idempotency_key`+`request_hash` 唯一、`status`、`phase`、`attempt`、`lease_until`、`payload_json`(含 `model_config`)、`artifact_json`、`settled_at` |
| `quota_events` | 每次成功精修的扣次事件 |
| `provider_calls` | 每次外部调用的模型、用量、耗时、状态（UNKNOWN 表示结果不明） |
| `expired_requests` | 过期任务的幂等墓碑（owner+key+request_hash），防止过期重放再次付费 |
| `cleanup_paths` | 待删路径持久队列（崩溃/占用后可重试） |
| `outbox_events` | 任务入队事件（worker 认领时标记已送达） |

## 6. 任务流水线（状态机）

```
POST generate/refinements → submit()
   幂等键查重（jobs 或 expired_requests）→ 校验作品/额度/基准版本
   → jobs=QUEUED + outbox + designs.active_job_id
worker_loop（0.5s 轮询）→ claim_job()：QUEUED 或租约过期的 RUNNING/RECONCILING
   → RUNNING（attempt+1，lease 600s，心跳续租）
   → build_artifact()
       校验所有输入素材哈希 → refine: provider.plan() 受控计划（≤8 条操作）
       parameters: 范围校验（scale .2–2.5、spacing .4–3、rotation ±360、offset ±宽高、背景色 #RRGGBB）
       edit_asset / edit_background / edit_composite: 调图片模型 → 派生新素材
       → render() 合成 master.png + preview.png → validate_image() 校验尺寸/DPI/格式
   → checkpoint()：写 artifact.json（fsync）+ 记入 jobs.artifact_json
   → complete_job()：再校验哈希与租约 → 事务写 assets/versions/quota_events/designs/jobs=SUCCEEDED
失败：fail_job() 置 FAILED、不清额度；需要补充说明时 needs_clarification=1
中断恢复：attempt 目录里已有 artifact.json 就只重做提交；模型调用结果不明时不重发
```

关键约束：**同一个作品同一时间只有一个活动任务**（`active_job_id`）；精修要求 `base_version_id == current_version_id`；
提交成功但客户端断线可用同一幂等键安全重试。

## 7. 模型路线

| 路线 | 计划（理解要求） | 出图 | 配置 |
| --- | --- | --- | --- |
| `openai` | Responses + JSON Schema（`text.format`） | Images 生成/编辑，内联图片结果 | 独立 Key、语言模型 ID、图片模型 ID |
| `deepseek_seedream` | DeepSeek JSON 计划（复用现有 Key 池） | 火山方舟 Seedream（复用火山 Key） | 沿用现有 DeepSeek 与火山方舟设置 |
| `test` | 规则替身（仅明确句式） | 本地 PIL 画随机底图 | 仅开发/测试；线上 `hsd` 模式拒绝真实任务用 test |

- 任务在 `submit()` 时把 `model_config` 快照写进 `payload_json`；执行时 `provider_for_job()` 比对
  `config_revision`，设置变了就明确失败，不偷偷换模型。
- `ai_ready` 需同时满足：`enabled` + 语言模型 + 图片模型 + 对应 Key（或继承的 Key 池/火山 Key）。
  **线上默认 `enabled=false`、`ai_ready=false`**，管理员需在「Key 账本 → 丝带设计」主动启用。
- 未知结果（超时/无响应）标 `UNKNOWN`，不自动重发；失败不扣精修次数，但外部调用可能已计费。

## 8. 渲染与输出

- 6 种排版：`grid` 整齐平铺、`stagger` 错位平铺、`scatter` 随机散点、`single` 单排重复、
  `ends` 两端主图、`panels` 分区拼接；规则 `rows`、`step_ratio`、`motif_ratio`。
- 参数：`scale`、`spacing`、`rotation`、`offset_x/y`、`background_color`；`seed` 固定保证可复现。
- **参数目前作用于全部图案**，不支持只调某一个；要求会被拒绝并请用户说明（已知边界）。
- 当前生效的输出配置（2026-10-29 与设计师确认）：**300 DPI、RGB、PNG**；含出血总高 4.4 cm（成品 3.8 cm + 上下各 0.3 cm 出血），长度方向不留出血；画布按 100 cm 长落图，即 **11811×520 px**，本地渲染实测约 0.5 秒、72 个图案位置。
  长度不固定：改输出配置即可换长度（宽 64–16000、高 64–5000、总像素 ≤4000 万、DPI 72–1200、只支持 PNG）；若要「每个作品自选长度」或「循环单元」，需要改代码（per-design 画布），目前是全局单一配置。
- 母版落地即校验：尺寸/DPI/格式/模式 + sha256；预览单独哈希；被替换后拒绝下载。

## 9. 保留与清理（50 小时）

- 共享 `RETENTION_SECONDS`；清理在 worker 里**每 10 分钟**跑一次，按 owner 整批处理。
- 只要 owner 有活动任务/租约/未结算，整批跳过；`design.retained_at` 与相关 `job.settled_at` 取最大判断。
- 资产引用链（含 `derived_from` 与 `composite_ref`）会被保留，避免删掉被新作品复用的素材。
- 删除先写 `cleanup_paths` 再删文件，失败可重试；路径必须在本模块 `assets/`、`jobs/` 下且无符号链接。
- 过期任务的幂等墓碑**永不删除**（防重复扣费），行数随历史请求增长——目前无归档策略。

## 10. 安全边界

- 全部接口经宿主会话鉴权；`/api/ribbon/admin/*` 二次校验管理员；管理员设置接口在
  `/api/admin/ribbon-settings`（需 `expected_revision`，冲突回 409）。
- Key 加密保存（Linux AES-256-GCM，Windows DPAPI），普通接口与员工页面不回显；
  模型 ID 只在管理员页面按需显示/复制。
- 上传单文件 20 MiB / 4000 万像素（与图号工具不限固定字节的规则不同）；跨站写请求拒绝；
  API 响应 `no-store`；前端在 ShadowDOM 内，`X-Frame-Options: DENY`。
- 模型输出像素 ≤4000 万，磁盘与内存写入前预检（`space_reserver`、`memory_bounded_operation`）。

## 11. 已知边界与风险（研发时优先考虑）

1. **真实模型效果未验收**：文字保真、清晰度、纹理接缝、Seedream 尺寸/透明背景限制都只在模拟接口上验证过。
2. **单 worker 串行**：所有 ribbon 任务（含底图）在一个线程里顺序执行；一次长图调用会阻塞其他人的任务。
3. **精修额度硬上限 2 次**（数据库 CHECK + 服务校验），产品若要改需同时动 SQL 与迁移。
4. **参数粒度**：只能整体调，不能单独调某个图案的位置/缩放；整幅编辑后失去图层参数能力（`capabilities` 变 `composite_edit`）。
5. **`expired_requests` 无上限增长**：长期运行需要归档方案，但必须保留幂等唯一性。
6. **前端产物入库**：`hsd_tool/static/ribbon/ribbon.js` 是构建产物（约 1 万行），改 `ribbon_frontend/` 后必须 `pnpm build` 并提交产物。
7. **管理员总览无分页**（jobs/provider_calls 各取最近 100 条）。
8. 多实例 / 外部数据库未验收；不要加 Gunicorn worker。
9. 现用的 300 DPI/RGB/4.4 cm 规格已按设计师要求配置，但尚未做印刷打样；打样前不要承诺颜色与套准。长度方向目前固定 100 cm 画布。

## 13. 还需要你确认的产品问题

1. 长度到底怎么定：固定画布（现为 100 cm）？还是每个作品自选长度？还是做成可无缝循环的单元（如 20 cm）？这决定要不要改代码。
2. 两次精修是否够用？是否按作品、按员工或按时间放宽？额度规则要不要可配置。
3. 「只调某个图案」是不是常用需求？若是，计划要扩展成按图层目标的结构化计划。
4. 底图生成是否也计费/限量？目前不占精修额度、不限次（只有"同时一个底图任务"的限制）。
5. 共享素材库由谁维护、是否需要审核流程；个人素材 50 小时后是否要转成共享库素材。
