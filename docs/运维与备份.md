# 服务器运维与备份

本文只记录**这台已上线服务器**（阿里云 `39.106.45.116`，HTTPS 8443）的实际路径与操作方式。
所有命令都需要在服务器上以 root 执行；除 `backup.sh` 外都不写业务数据。

## 1. 组成与路径

| 用途 | 路径 |
| --- | --- |
| 服务单元 | `/etc/systemd/system/hsd-agent.service`（模板 `deploy/hsd-agent.service.example`） |
| 环境变量 | `/etc/hsd-agent/service.env`（root 640） |
| 私有配置目录 | `/etc/hsd-agent/private`（`hsd-agent:hsd-agent` 700），含 AES 机器密钥与服务码 |
| 代码发布 | `/opt/hsd-agent/releases/<sha>`，`/opt/hsd-agent/current` 软链指向当前版本 |
| Python 环境 | `/opt/hsd-agent/venv`（部署脚本创建，勿手工装包） |
| 数据卷 | `/var/lib/hsd-agent/storage`（独立 ext4，挂载失败时服务拒绝启动） |
| 任务数据 | `storage/data/{jobs,uploads,employee_outputs,material_tasks,task_records}` |
| 设置与账本 | `/var/lib/hsd-agent/settings`（含访问码注册表、加密后的模型 Key、用量记录） |
| Nginx | `8443` TLS 终结 → `127.0.0.1:8830` Gunicorn（单 worker） |

## 2. 日常检查（只读）

```bash
systemctl is-active hsd-agent.service
curl -sk -H 'Host: 39.106.45.116:8443' https://127.0.0.1:8443/healthz      # 期望 ok
journalctl -u hsd-agent.service --since -1h -p warning
df -h /var/lib/hsd-agent/storage                                          # 关注可用空间
readlink -f /opt/hsd-agent/current                                        # 当前版本
bash /tmp/check_busy.sh                                                   # 期望 busy jobs: 0
```

`/healthz` 是无登录的最小存活探针，只返回 `ok`，不含版本、实例或任何配置。
详细状态（`/api/health`）仍要求员工登录，避免把部署细节暴露给未认证访问者。

## 3. 健康探针与告警

`deploy/hsd-healthcheck.sh` 只读检查四件事：服务是否 active、`/healthz` 是否 200、
数据卷是否已挂载且剩余空间 ≥ 1 GiB、进程数是否为单实例。**它不会重启服务**，
失败时写一条 `ALERT ...` 到 journal，并让该单元变成 failed。

安装（一次性）：

```bash
install -D -m 0755 deploy/hsd-healthcheck.sh /usr/local/lib/hsd-agent/hsd-healthcheck.sh
install -m 0644 deploy/hsd-healthcheck.service deploy/hsd-healthcheck.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now hsd-healthcheck.timer
systemctl start hsd-healthcheck.service && journalctl -u hsd-healthcheck -n 5
```

查看结果：

```bash
journalctl -u hsd-healthcheck --since -1h
systemctl --failed            # 探针失败会出现在这里
```

这是一条**本地告警**，不会发短信/邮件；需要外部通知时，把 `journalctl` 输出接到现有监控即可。

## 4. 备份

不可重建的只有两类：`/etc/hsd-agent`（机器密钥、服务码）与 `/var/lib/hsd-agent/settings`
（加密 Key、访问码哈希、用量）。上传图片和结果 50 小时后自动清理，不进备份。

```bash
bash deploy/backup.sh                     # 默认写到 /var/backups/hsd-agent
bash deploy/backup.sh /root/hsd-backups   # 指定目录
```

脚本用 `tar -czf` 打包，`gzip -t` 校验，权限 600，并生成 `.sha256`。
**备份包含密文与哈希，仍然是敏感文件**：不要提交 Git、不要放公共网盘、不要贴进聊天。

建议：每周一次，拷到服务器以外（加密 U 盘或对象存储私有桶），保留最近 4 份。

### 恢复

```bash
systemctl stop hsd-agent.service
tar -xzf hsd-agent-<时间>.tar.gz -C /
chown -R hsd-agent:hsd-agent /var/lib/hsd-agent/settings
chown -R root:root /etc/hsd-agent && chmod 600 /etc/hsd-agent/service.env
systemctl start hsd-agent.service
curl -sk -H 'Host: 39.106.45.116:8443' https://127.0.0.1:8443/healthz
```

恢复后旧员工会话不回来（设计如此），员工用访问码重新登录即可看到 50 小时内的旧任务。

## 5. 磁盘与保留期

- 云模式只保留 **50 小时（约两天）**：任务处理结束、成功编辑或再次处理后开始计时；排队/运行/预览/下载中的任务不会被清理。
- 数据卷 **15 GiB**（2026-10-29 由 12 GiB 在线扩容，镜像文件从 12 GiB 扩到 15 GiB，`losetup -c` + `resize2fs` 完成，期间不停服务）：扩容后已用 10.2 GiB、剩 4 436 MB（71%）。此前 12 GiB 时在 81% 与 89% 之间来回，属工作集大小，不是泄漏。
- 扩容用掉的是根盘空间（`fallocate` 预留），本次根盘空闲由 11 075 MB 降到 8 051 MB；要继续扩容先确认根盘还剩多少、同机另一项目的数据库增长空间够不够。
- **`storage/tmp` 是服务的 `TMPDIR`**（unit 里 `TMPDIR=/var/lib/hsd-agent/storage/tmp`），目录本身绝不能删，服务运行时的临时文件会写进去并自行清理。里面如果出现 `ribbon-acceptance`、`real-gunicorn-check-*` 这类**验收残留**，可以人工确认后清。
- `storage/acceptance` 不被运行时代码使用，跑验收/测试会往里写文件，也不自动清理；2026-10-28 经用户确认清空过一次（回收 889 MB，只删内容、保留目录本身与 `lost+found`）。删除前需确认服务 active、`busy jobs: 0`、目录解析路径正确。
- 探针在剩余 < 1 GiB 时告警。真到告警时，先确认没有人工验收目录要留，再按最旧任务目录清理；不要清 `settings`、`jobs` 里正在跑的任务。
- 单张拼图批次的输出可达 130–240 MB，密集批次会明显吃空间。

## 6. 升级与回滚

```powershell
# 本机
git archive --format=tar.gz -o tmp/release.tgz HEAD
(git rev-parse HEAD).Trim() | Set-Content -NoNewline tmp\release-sha
scp tmp\release.tgz tmp\release-sha hsd-server:/tmp/
ssh hsd-server "bash /tmp/deploy.sh"
```

部署前必须确认 `busy jobs: 0`；部署会中断正在跑的任务。回滚：

```bash
ls /opt/hsd-agent/releases
ln -sfn /opt/hsd-agent/releases/<旧sha> /opt/hsd-agent/current
systemctl restart hsd-agent.service
```

旧 release 目录保留 25 份（约 75 MB），不要手工删当前版本。

## 7. 故障处置

- **服务卡住 / 停止很久没退出**：单元是 `TimeoutStopSec=infinity` + `SendSIGKILL=no`，
  设计上要等已接受的 AI 调用收敛并记账，所以停止可能持续数分钟。确认仍然卡死时，
  用 `systemctl kill -s SIGKILL hsd-agent.service`，再启动；已经发出的调用可能变成
  「计费未知」，页面会保留记录、不会自动重发。
- **不要**通过加 worker、开 `--reload` 或起第二个实例扩容：会话与任务归属建立在单进程内存上，多实例会互相覆盖。
- **不要**把 `MemoryMax` 调大来「解决」慢：上限是资源隔离，不是性能开关。
- **访问码失效/新增**：管理员从网站「Key 账本 → 员工访问码」处理，不需要改服务器文件。

## 8. 安全边界（不要放宽）

- 凭据只以 AES-256-GCM 密文存于 `settings`，机器密钥在 `/etc/hsd-agent/private`，二者分离。
- 访问码只存带盐哈希；管理员密码只存 PBKDF2 哈希。
- 只有 `/api/admin/ledger` 与 `/api/admin/material-key` 允许在**管理员已认证**时返回明文，其余接口一律不回显。
- 日志只记请求行与用量，不记 Key、访问码、图片内容；`/healthz` 不含部署信息。
- 主机专属操作（选择文件、打开目录、退出进程）在云模式一律禁用，这是设计而非缺失。
