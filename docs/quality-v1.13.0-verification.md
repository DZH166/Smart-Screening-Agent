# v1.13.0 员工停止与实测前质量验证

本版基于 main `15b7f9b`（v1.12.1），不改变匹配阈值、编号、DeepSeek发送范围或业务自动通过资格。仅云实例增加同浏览器签名任务恢复；旧 Windows/LAN 恢复边界保留。不接 OSS，不制作新 Windows 包。

## 交付行为

- 上传响应丢失后先核对请求 ID；同 ID 不重复启动整批，跨员工不能查询或复用归属。上传停止先登记取消，再阻止晚到提交；LAN/云都在后台提交前登记。
- 处理中可以停止本批，只有自身父任务、子核验和已发送请求收敛才进入 cancelled。不能导出已取消批次，不能回滚已产生的调用用量，不能中断一次原生 CV 调用的内部执行。
- 云任务使用私有 HMAC 快照与独立恢复 Cookie，重新认证后只恢复自己的同版本未过期任务。忙态不自动续跑，结果与全部比较素材仍须校验。更换浏览器、清 Cookie、版本/实现变化和三天到期均不恢复；下载不延长三天保留期。
- 256 MiB 是共享准备缓存的计量预算，另有原有 64 MiB 纹样 scratch；解码、OpenCV、编码和模型请求另占内存，不能视为进程 RSS 上限或任意规模承载保证。缓存使用无 pickle NPZ，精确恢复像素、KeyPoint、描述符及颜色信息，按随机任务 namespace 隔离。AI 图片准备另有每批128 MiB编码预算，超过时不发送删减过的候选库，继续完整本机核验并明确记录。新增磁盘写读有成本，不声明整体加速。
- 过期任务清理不再等待全部员工空闲，扫描移出全局锁并在删除前复查租约与本任务工作。错误签名、链接或未知目录保留。
- 下载失败留主页面；管理员账本按需读取并在收起/失效/离开时销毁，退出失败不显示成功。无费用或调试大面板。

## 审查与验证方法

使用合成数据注入上传回包丢失、上传提交前取消、CPU排队/运行、模拟模型在途、导出在途、会话过期/重新认证、版本冲突、下载预检成功后实际失败、跨员工访问和清理租约竞态。合成模型用量仅验证记账，不构成模型效果或资格证明。

审查中发现并修复：停止请求缺少 expected_revision、占位任务未获取真实 revision、LAN 上传提交后才登记取消、线程取消上下文未传播、CPU子核验排队不能及时取消、发送前再次检查停止标记，以及旧下载/上传回包干扰下一批。

最终生产代码与 Linux 验证快照逐文件 SHA 核对一致。执行结果：

60张最终生产代码单轮145.874秒；升级前单轮143.562秒。早期192MiB预算单轮183.461秒，随后补O(1)成员检查并采用常规256MiB预算后两轮为151.018/145.874秒。早期运行与其他本机检查并行且没有冻结系统负载，这些不是受控速度基准，不能推导提速/退化百分比；完整保存所有运行，未挑选或覆盖失败/较慢结果。主要改善是停止、恢复、重复任务和内存驻留边界，而非算法加速。

实际浏览器使用明确标注的合成图片/模拟接口，检查1366×768和1920×1080；另在1093×614可用窗口检查管理员页无横向溢出。导入主按钮和审核主按钮在1366×768首屏可见；实际点击停止经过cancelling后显示cancelled；下载实际失败保留完成页并提供重试；管理员账本收起后DOM明文为空。原生浏览器缩放未独立量化，不把紧凑窗口测试冒充系统缩放实测。截图与测试输出在本机tmp，不进入Git或附件。

全部场景未调用真实DeepSeek、未激活资格；合成用量只验证记账。Linux/Windows跳过条件不同，不把两平台总数相加成独立案例数量。发布必须从干净提交的Git字节组装白名单源码归档，排除现有业务核验JSON，核对源文件/归档SHA后再激活；回读HTTPS版本、静态文件、原有两Key配置及原站健康，核验成功才发布Release。

## 独立业务实测

旧60张仅作回归；10.12不用于本版。没有额外已确认的新业务批次，不能宣称新图案准确率或人工工时提升。员工试用时先冻结独立核对结果，再比较错误自动通过数、人工审核张数、未处理原因和整批耗时；这属于实测验收，不增加日常逐图检查步骤。

首次多人试用由小批次开始，再用实际日常最大批次和人数验证内存/磁盘/队列；故障应保留全部失败记录，不挑选有利结果。不以点击数或旧候选命中率代替准确性验证。
