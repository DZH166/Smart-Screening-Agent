# 底纹精修专项修复

状态：独立分支 `codex/ribbon-background-refine`，基于远端 main `5ea0b32` 开发，验证中；未合并或部署网站。

## 本次问题

对用户反馈的“帮我把背景铺满星星”任务进行了线上只读核查。实际执行了 DeepSeek 文字规划和 Seedream 底纹编辑，目标是独立背景，原前景素材、几何参数未改，未发生错误模型路由。

保存的规划擅自增加了“细小、低对比度、柔和”等限制。原图片编辑器又使用通用的“保持原有背景”指令。返回底纹仅有极淡的小装饰变化，随后继续按作品已有的柔和显示设置合成并缩小，最终难以辨认。调用成功和存在像素变化不能证明已满足“铺满星星”。任务与图片证据只在本机私有目录保留。

## 修复边界

- 选择底纹或某区底纹时，图片编辑直接保留员工原要求，不再仅使用规划器重写的短句。整体布局下只传递可明确分离的底纹子句，避免人物修改要求混入底纹。
- 明确的底纹内容要求不能被纯排版参数冒充完成；纯底纹要求也不能附带未经要求的前景修改。冲突时保留原版本，不计成功精修次数。
- 图片编辑使用独立底纹指令，保留覆盖范围、数量、疏密、添加/移除/替换的意思；不擅自要求极小、低对比度装饰。人物、原文字仍由程序叠放。
- 保持员工原先选择的柔和/原色显示，不通过静默取消柔和效果制造“优化”。不增加自动图片重试、二次精修或模型自评。
- 新增文字保护是有限规则，不能证明任意自然语言理解正确。无高把握的表达保留原受控规划路径；明确混合且无法隔离的要求需澄清。
- 原版本、下载、归属、50小时保留、幂等与两次成功精修规则保持。技术图像变化检查仍不是语义或印刷质量验收。

## 验证

最终测试、真实模型对照、独立复核和提交信息将在完成后补记。真实输出和截图不提交 Git，也不作为通用成功率证明。
