## 1. 分区排版的 offset_x 破坏分区隔离（已复现）

`split` / `panels` / `stacked` 的语义是“每个分区独立排图案、独立底纹”。但横向位置参数 `offset_x`
在两处按**整幅单元**循环位移：

- 前景：`ribbon_backend/loop_layout_v2.py:269-274`
  先检查“是否跨分区”，再执行 `x = (x + ox % width) % width`。跨分区检查发生在循环位移之前，
  所以位移后可以越过分区边界而不报错。
- 底纹：`ribbon_backend/loop_pipeline_v2.py:143-147`
  `ImageChops.offset(canvas, offset, 0)` 把**整张已填好的画布**滚动，分区颜色/底纹随之互换。

可达路径：精修参数允许 `offset_x`（`ribbon_backend/providers.py:355-360`，默认 20px，也接受“右移 200 像素”），
上限为 ±输出宽度（`service.py:1025`）。

复现（本地探针，合成图）：

```
panels n=3, offset=0   -> 分区图案数 [2,1,1]
panels n=3, offset=300 -> 分区图案数 [1,2,1]     # 图案跨区
panels 三色分区, offset=100（横向位置像素）:
  x=1/101/201/299 颜色 红/绿/蓝  ->  蓝/红/绿      # 整幅滚动，分区身份丢失
```

建议修法（二选一，需要产品确认）：

- **A. 分区内位移**：分区模式下把 `offset_x` 按分区宽度取模，前景 `x = zone_left + ((x-zone_left+ox) % zone_width)`，
  底纹只滚动本分区内容。语义仍是“整体右移”，但不破坏分区。
- **B. 分区模式禁用位移**：`split/panels/stacked` 收到非零 `offset_x` 时明确报错，提示改用逐分区调整。

## 2. 图案放大没有上限也没有提示（质量）

`ribbon_backend/loop_layout.py:_size()` 只按“可用高度”等比缩放，不比较源图像素；
`loop_layout_v2.py:192` 直接把 `base * factor * slot_scales` 作为目标高度。实测（`single` 模式，520px 高）：

```
源 64px  -> 目标 314px (4.9x)
源 128px -> 目标 314px (2.5x)
源 256px -> 目标 314px (1.2x)
```

`layout_quality.py:130` 的老引擎会用 `natural_height * max(1, scale)` 限高，v2 没有这层保护，
所以同一张图在两个引擎下的画质保障不一致；输出仍是“checked”，页面不会提示放大倍数。

建议：加“放大倍数”诊断（`target_height / source_height`），超过阈值（例如 1.5×）写进 `loop.issues`
并标 `needs_review`；是否硬性限幅（如 2×）需要产品确认，因为限幅会让小图案排不满行高。

## 3. 前端分区高亮与 offset

`ribbon_frontend/src/App.tsx:289-291` 的高亮框用 `(index*w/zones.length + offset) % w`，
与当前后端的整幅滚动一致。修 #1 时此处要同步改为分区内位移或直接不再叠加 offset，
否则高亮框会指向错误位置。

## 4. 尺寸标签容易误读

`App.tsx:508-513` 用 `output_profile` 显示“宽×高 px · DPI · cm”。v1.25 起 `output_profile.width`
是**循环单元宽度**（按图案与整数周期算出），例如 439px ≈ 3.7cm，而不是 100cm。
规格本身是用户确认过的，但界面没有说明“下载为一个单元、按需重复”。建议在“输出详情”里补一行
“按 100cm 成品约需 N 个单元”，避免被当成规格回退。

## 5. 底图任务没有次数限制

`service.py:919-923` 对 `kind='background'` 只限制同时 1 个，没有次数或频率上限；每点一次“生成底图”
就是一次付费图片调用。目前依赖员工自觉。是否需要限制（例如每作品 N 次或按小时）由产品定。

## 已核对、不是缺陷的部分

- **精修 no-op 不扣次**：`complete_job` 在写版本前用 `same_rgba_pixels` 比较，相同像素抛 `ClarificationNeeded`，
  不建版本、不加 `successful_refinement_count`（`service.py:1425-1432`）。
- **额度并发**：`active_job_id` 串行化同作品任务；提交与提交入库两处都检查 2 次上限（`service.py:909,1443`）。
- **单元边缘重复绘制**：`loop_layout.paint` 对跨边界图案做 ±width 复制，这是循环单元的正确做法，不是粘贴错误。
- **保留期清理**：共享素材、被引用素材与活动任务都有保护（`retention.py:136-165`）。
- **软删除后可下载**：删除是 50 小时内可恢复的软删除，删除后仍可按版本 URL 下载，属于既有约定。
